# 新 CAN 电机控制适配

把用户指定的电机接入现有框架。交付范围由用户决定：协议调查、离线适配、ROS 接入或已授权台架验证，不将每次调用都扩展成全阶段开发。软件适配与实机验收分别报告。

## 恢复并确定范围

1. 定位 Git 根，读取适用 `AGENTS.md`、branch/HEAD/status/diff。按仓库约定使用 project-memory；缺少时执行仓库协作流程规定的等价恢复，不声称已运行 skill。保留用户改动，遵守分支/PR 规则；本 Skill 不自动授权推送、合并或外部消息。
2. 读取当前 `docs/planning/README.md`、`docs/development/adapter_contract_v1.md` 及相关 ADR。用 [代码地图](references/repository-map.md) 查实际接口；本次代码/测试优先于本 Skill 快照。地图中的路径均相对目标仓库根，不是 Skill 安装目录。
3. 核实电机与驱动器型号、固件、目标控制模式、通信设备和本轮授权范围。先查已有资料，只追问影响当前步骤的缺失信息，同时继续不依赖它的离线工作。可将 [适配计划模板](assets/adapter-plan.md) 合入现有正式设计，不另建平行项目记忆。
4. 简述交付目标、新增/复用层和待确认项再实施。用户只要求调查或评审时，不擅自改生产代码。

## 选择正确的扩展层

| 情况 | 工作范围 |
|---|---|
| 同协议、兼容固件、已支持模式，再加一台 | 复用适配器/runtime；新增 ID、路由、关节、标定和限位配置，逐台验证并检查总线负载 |
| 新协议或不兼容固件 | 新增 `mech_protocol_<device>` codec/session，配置期固定 profile；部署层新增必要参数解析、runtime 和生产组合 |
| 已有协议增加模式 | 先查 wire/session 是否已支持，只补缺失层，不按模式复制整套包 |
| 电机不变但 USB-CAN 网关不同 | 优先适配 transport，不能把网关封装塞进电机 codec |
| 当前统一接口不能表达目标能力 | 说明缺口与最小通用扩展，按项目 ADR 流程处理；禁止在控制器或通用硬件中加品牌分支 |

同品牌不等于同协议；同为 CAN 不等于指令兼容。当前 AK3.0 runtime、组合插件和操作工具并非任意品牌即插即用。

## 协议与能力证据

- 分开记录**文档规定、本轮设备读回、用户提供、历史记录、推断、未知**及适用版本。供应商资料遵循当前 manifest/许可规则，不擅自提交受限原件。
- 先匹配驱动板/固件再选手册。提取 ID、帧型、DLC、端序、符号、缩放、校验/分片、命令/反馈周期、序号/时间、使能/失能、故障与模式切换。
- 区分 USB 串口 baud、CAN 仲裁率、CAN-FD 数据段率。Classic 帧不使用 BRS；实际值及板固件不能从 SDK 默认值、历史 4.8.8 或另一个通道推定。`*_verified` 只在满足当前能力契约的真实读回证据下置真。
- 明确可导出的命令/状态子集。position/velocity/effort 使用标准物理含义；电机轴/输出轴、减速比、方向、零偏、圈数、限位要有依据。电流/raw 值不能直接充当 N·m；未知状态不能用零伪造。
- 只实现请求模式。缺关键字段时标记对应能力未完成，不猜常量；无硬件也可完成有证据支撑的离线部分。

## 分层实现

### Codec 与 session

- Codec 负责有效帧和设备数据的转换，无 ROS、端口 I/O、设备探测或 sleep；活动路径遵守仓库有界、无阻塞、无动态分配约束。
- Session 管理固定 profile、状态机、范围、反馈质量、期限、故障和恢复。读取当前 `adapter_template.hpp` 与成熟实现；多帧/握手协议不适合旧接口时明确契约缺口，不硬塞成一帧或自动猜模式。
- Golden vectors 来自文档或独立已验证样本，不能只用自己 encode/decode 互相证明正确。保留 raw 故障、设备时间与主机到达时间。
- 注入时钟和传输抽象；适配器不创建物理通道。控制帧经过每条物理总线唯一的 `BusRuntime` 写者，不给每个 session 独立发送线程或竞争同一接收流。

### Runtime 与 ROS 组合

- 在 `mech_bringup` 增加必要的 `RuntimePort`、参数校验、生产插件注册和配置；复用 `CompositeSystem` 生命周期、claim/switch。正常适配不重写 core/通用硬件/控制器；profile 显式注册是受控扩展，不是允许厂商逻辑进入 core。
- 按当前 `CommandDispatch` 契约处理：`authorized=false` 撤销该资源 pending；`fresh=false` 不接受新命令，但不能仅因此取消仍在原期限内的 pending。
- 先处理已有命令过期/反馈失效，再接受新目标；新目标不能抹去已经违约的旧期限。切换、停用、清理和重启不能重放旧目标；无 claim 不发电机控制命令，必要管理报文另外定义。
- 仅导出真实支持的状态和命令组合；整组 claim/release。兼容标准 JTC 时保留当前可选 generation 强/弱档，不强迫标准控制器使用私有接口，不把硬件循环当作上游目标刷新。
- 同一物理总线上的不同设备共享调度与路由，不通过多个插件重复打开同一通道拼接。现有组合不支持异构设备时，明确这项额外工作。
- 接通实际 launch→生产插件→runtime→session→transport。核对 CMake/package/plugin XML、schema、xacro/YAML/launch 和参数报错；loopback/fake 成功不能当作生产路径已接通。
- 复用接口匹配的现有控制器/JTC。位置电机不能仅靠配置获得力矩能力；新控制算法按用户范围另处理，不藏进 codec。

### 标定、停止与诊断

- CubeMars 的 ID、模式号、增益、3/6ms 或 4/6ms、50Hz/60ms、范围及零偏均为具体实例，不作为新电机默认值。根据新设备周期、能力及保护要求选择参数并记录依据。
- 区分停止提交、取消 pending、设备失能/制动/保持和机械静止；deactivate 或 ACK 不自动证明已停止。失能工具遵守同一端口互斥并按新协议验证。
- 日志关联上游目标、claim/generation、编码帧、实际 TX/RX、反馈与首故障；有界保留，失败/取消仍可取证。缓存数值不冒充有效的新鲜反馈。

## 验证与交付

测试前读 [验证矩阵](references/validation.md)；设计/故障分析时按相关主题读 [CubeMars 经验](references/cubemars-lessons.md)，不把历史实例当新设备事实。

按任务范围推进 wire/session 离线 → runtime/生产插件与真实 controller_manager 的模拟通信集成 → 普通完整 CI → 已授权台架。Windows 结果不冒充 Linux/ARM64、实时或物理验证。

实机动作前核对本轮授权及适用 G0–G3；调用本 Skill 不授权启用 CAN、写电机、改 Jetson 系统或部署。已有明确授权且条件满足时不重复询问。未授权时完成可做的离线代码、文档和具体验收方案；不自动探测、置零、刷固件或运行电机。

新增包进入当前依赖解析、包清单、报告与依赖方向检查。普通 PR 跑普通完整矩阵；只有时钟/CI 改动等适用条件才使用仓库规定专项长测，不要求每次适配跑 20 轮。

最后报告支持的模式/版本、新增与复用层、精确提交与测试范围、未验证能力和下一步。区分配置、构建、离线、实机完成度。按仓库约定更新并验证 memory；handoff 仅按真实触发事件创建。
