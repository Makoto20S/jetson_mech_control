# PH-EXO 阻抗调参面板
## 连续往返（2026-11-17）

独立入口 `Open-Bench.ps1` 已接现有连续参考接口；仍复用同一个普通阻抗控制器。
默认 Kψ=Kβ=20、Bψ=Bβ=0.3；每台目标力矩10 N·m、反馈电流6 A、相对启动编码器位移±90°。
K/B及这些限幅在开始前填写，运行中不修改；没有预设保持时长，手动停止。

| 填写方法 | 行为 |
|---|---|
| 目标ψ/β、往返幅度都留空 | 保持启动姿态 |
| 填两轴目标、幅度留空 | 平滑到目标后保持 |
| 填两轴幅度、目标留空 | 以启动姿态为基准连续往返 |
| 目标和幅度均填写 | 先平滑到基准目标，再连续往返 |

两轴幅度必须同时填写，不动的轴填0；至少一轴非零。幅度是有符号偏移，
例如ψ=3°、β=−2°表示ψ先向正侧，再向负侧，覆盖基准±3°；β走“基准→基准−2°→基准”。
周期分别填写，单位秒，含去程和回程；默认6秒，支持1～60秒。
ψ幅度支持±45°，β有符号偏移支持±53°，但整条参考必须位于当前模型域ψ[−45,45]°、β[−8,45]°，
并通过相对编码器位移预检。

1秒捕获后开始；有目标时先按“过渡”秒数接近目标。去程、回程采用五次平滑函数，
位置/速度/加速度在起点和转向点连续。没有新增控制节点或实时控制律；
worker每20ms提交同一 `ImpedanceRef` 的q/dq，原生控制器继续5ms更新。
参考过期、停止、急停、返回调试沿用现有流程，不自动重新启动。

新增短字段是 `amp_deg:[ψ,β]`、`period_s:[ψ,β]`；与可选的`pose_deg/move_s`可组合。
导入旧参数时没有这两个字段就继续固定模式。六张电机波形保留，状态栏显示机构角度与当前参考。
本轮入口在独立调参模式；ROS系统入口的上层管理服务仍保持原合同，不通过连续重启伪装动态参考。

Windows回归与Orin软件结果见连续往返验证（项目本地记录 roundtrip_panel_20261117.md）。
2026-11-17用户接受当前波动，连续目标阻抗及此入口按样机阶段验收通过；后续再验证调参。原始数值结果保留，本轮未启动真实电机。

### 使用顺序

1. 在 Orin 启动已经配置好的 controller_manager、控制器、状态节点及上层节点；
   上层节点使用 policy: ph_exo_fixed_pose，具体入口见上层接口说明。控制器初始 inactive。
   本界面不会启动/结束共享 manager，不在运行中改写硬件 URDF。
2. 点击“连接 ROS”只读取当前状态。默认服务前缀 /exoskeleton/impedance，参数节点 /exoskeleton_control。
3. 在 debug 状态填写两轴 K、B 及两台电机的目标力矩上限，点击开始。
   客户端原子设置 hold.k/b/tau，然后调用 start；以 ROS 返回 running 为进入保持的依据。
4. 停止/软件急停分别调用 stop/emergency_stop；服务接收成功不等于停止已确认。
5. “返回调试”在每个阶段均可点击，立即恢复初始页面并保留所填参数。
   已发启动请求时自动编排 stop→新停止确认→reset，未启机的只读连接直接取消。
   ROS实际状态在下方单独显示；复位成功后，下一轮仍需手动点击开始。

有命名空间时，直接运行电脑端 Python 入口并指定 --api /前缀/exoskeleton/impedance --node /前缀/exoskeleton_control。
既有 SSH 目标及工作目录仍来自 config/parallel_exo/orin_sync.json；客户端与上层节点需使用同一 ROS domain。
远端入口只桥接 ROS，不打开串口，不直接生成 MIT 帧或独立失能报文。

### 参数、状态与波形

- 新参数文件只有短字段：k:[ψ,β]、b:[ψ,β]、tau:[104,105]。
- 默认仍为 K=10、B=0、每台目标力矩上限10 N·m；实际可用范围由 ROS 后端再次校验。
  软件后端沿用较小验证范围（例如 K=[2.4,2]、B=[0.18,0.15]、tau=[0.2,0.2]）。
- 电流与编码器位移停发条件由 ROS 硬件配置管理；ROS 界面不显示可编辑的无效输入。
  原脚本模式仍保留原来的三个限幅输入。
- 运行阶段、原因、q_ref、stop_ok、disable_ok 来自 ROS；stopped 与失能确认分别展示。
  simulation 的 stop_ok=true 不伪造电机应答，mit_pty 的应答是软件模拟；界面明确标记软件后端。
- 六张图仍为两电机的目标扭矩、输出轴速度 RPM、编码器角度。
  速度使用 RobotState 已确认的输出轴速度换算，不再在 ROS 模式硬编码极对数/减速比；
  缺失、非有限或过期数据留空，不画假零。
- 图表约20 Hz，不能作为5 ms实时截止期或轴端实测力矩证据。

## 手动停止与限幅

本面板**不设置保持时长**，启动后保持到点击停止、关页/失联或既有故障条件触发。
ROS底层通过显式bench_manual_stop参数取消该模式的30秒退出条件；
旧模式仍为30秒。没有延长命令租约、反馈时效或控制周期门槛。

| 输入 | 默认 | 当前支持范围 |
|---|---:|---:|
| Kψ、Kβ | 20 N·m/rad | (0,30] |
| Bψ、Bβ | 0.3 N·m·s/rad | [0,1] |
| 每台目标扭矩限幅 | 10 N·m | (0,10] |
| 每台反馈电流停发阈值 | 6 A | (0,6] |
| 电机相对启动角度范围 | ±90° | (0,90]° |

三个限幅对两台电机分别生效；角度是编码器位置相对各自启动位置，
不是ψ、β的机械工作域。力矩用于目标限幅，电流/角度越界用于停发，不混同。
数值范围沿用已支持上限，本轮没有提高其最大值。
参数仅在停止后修改，运行中锁定。旧含duration_s的面板参数文件会拒绝导入，
请从新版重新导出。

点击停止只代表请求；原脚本独立失能路径确认104、105应答且没有shutdown_error后，
才显示“失能已确认”。未确认时禁止再次启动。关页发送停止请求；
页面超过4秒无状态请求、SSH stdin EOF也请求停止，不自动重连/重启。保留现场急停。

## 软件急停（2026-11-14）

## 2026-11-15 独立入口：目标位姿

独立入口可填写目标ψ/β绝对机构角度和过渡秒数；两项留空保持启动姿态。
当前范围ψ[-45,45]°、β[−8,45]°；过渡1～60秒，默认3秒，之前有1秒参考捕获。
五次平滑参考到达目标后持续保持，K/B本轮固定，停止后才能修改。
它设置阻抗平衡位姿，不保证任意负载下零误差定位。

目标过渡期间允许电机相对启动位置±90°，到期恢复页面保持位移（默认±60°）。
最终目标超出保持位移范围时启动前拒绝。电流与力矩不放宽，仍按页面设置（最大6 A/10 N·m）。
固定启动姿态模式不使用这项过渡放宽；反馈、租约、故障和急停判断不变。
参考中断仍停发。当前ROS上层入口不增加这些目标输入，原独立脚本保留。

验证与实机数据分析见本轮记录（项目本地记录 target_pose_20261115.md）；界面六图仍为电机量，状态栏增加ψ/β及当前参考。

## 2026-11-15 后续更新：常态位移±90°

按用户最新要求，常态相对启动编码器位移默认值与可设置上限也改为±90°，覆盖上文默认±60°的记录。
界面仍可设置较小的保持位移范围；目标预检按当前输入值判断。过渡固定±90°，因此采用默认90°时不会在过渡后收紧。
电流最大6 A、每台目标力矩最大10 N·m、K/B范围及ψ/β模型范围不变。
旧导入参数中的60°会按原值保留，需在界面手动改为90°。
