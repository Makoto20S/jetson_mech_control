## 测量边界

- 实际链路：CtrBoard → USB-CAN 第五路（固定 by-id 的 if08，当前 ttyACM4）→ bridge → `/imu/imu1/data`、`/imu/imu2/data` → state callbacks → 100 Hz `/ref01/state` → observer。
- 在同一台 Orin 上使用 CLOCK_MONOTONIC；ROS 时间戳用于关联消息，不直接作为跨层延迟时钟。
- 起点是组成包的最后一帧交付前最近一次串口 read 完成时间，包含后续解析与发布；它不是 IMU 物理采样时刻、首字节到达或 CAN 线上时刻。
- 记录回调入口、处理结束、状态快照、发布入口/返回、GC 起止；测量期间使用预分配缓冲，结束后落盘。默认不开启探针。
- 状态节点定时相位由 ROS timer 的 time_until_next_call() 与两侧单调时钟读数估计。保存原始读数及整个 bracket 宽度；该宽度只约束启动锚点，不证明整个长测期间的释放格点仍准确对应每次 callback。
- 20/40 ms 间隔是诊断阈值；10 ms 状态周期用于观察格点统计，并非整机控制安全限值。周期、执行时间、数据年龄和观察延迟分别报告。
- 没有独立 IMU 采样序号，包时间连续不能证明每个 IMU 样本物理更新。没有电机反馈，不评价整机闭环。

## GC 与约 50 ms 间隔的证据

正式基线 observer 有 105 次 GC，其中一次 generation 2 持续 **28.946803 ms**，位于测量窗开始后 **168.264567317…168.293514120 s**。该 GC 覆盖 IMU1/2 长间隔的约 86.8%/87.0%，覆盖 state 长间隔的约 73.9%；state 进程测量窗内没有记录到 GC。

在这次 GC 正在运行的同一单调时间区间，bridge 仍发布包 `19847/19848/19849`，相对 GC 开始分别为 `+6.457/+16.461/+26.443 ms`；state 仍在 `+7.952/+17.169/+27.894 ms` 发布。三条 observer 流恢复后序列连续。因此长观察间隔的定位证据支持观察进程停顿及排队，而不是同长的设备或状态生产停顿。预分配缓冲减少记录器分配，并没有消除 Python/ROS 观察进程的 GC。

上述对照依次执行，CPU 动态频率和相位关系不同；不能把各组总 CPU 或分位数差值当作探针开销的严格因果估计。trace-off 没有链内探针，只能报告 observer 指标。短模型负载为固定状态逆动力学调用，20 s（含预热）内执行 4,000 次，200 Hz、0 次记录到的超期/跳槽，release 到完成最大 2.300 ms；它不消费实时 IMU，不构成闭环或长期并行负载验收。

测量开始后 220.055391 s，记录格点从 `25035 → 25037`，相邻 callback 实际只相隔 **11.155938 ms**。下一次 callback 的 start 却比被分配的 expected 早 **1.042102 ms**。全窗共有 **3,712** 次 start 早于 expected 超过 8.225 μs 锚点宽度，最小起始相位 **−3.010470 ms**；还有 542 次连 publish 返回都早于 expected。`slot=max(previous_slot+1, floor((start-phase)/period))` 的单向格点推进会在越界后保留格点偏置，当前这些记录已超出“锚点只有微秒不确定度”的解释能力。

最长连续 393 次名义超期位于测量开始后 204.293847…208.213962 s，此段实际相邻 callback 最大 **10.671126 ms**，不是一次约 3.93 s 停顿。全窗每次 publish 返回到下一次实际 callback 开始之间至少仍有 **5.057315 ms**；这证明本轮回调之间有可见余量，但不能替代对真实释放时刻的截止期评估。

state ROS 时间戳减 snapshot 单调时刻的首末差仅 −3.904 μs，没有足够证据把上述毫秒级相位趋势唯一归因于该时钟差；内部 steady timer 的每次预期释放时刻并未逐周期记录，也不能排除 timer/时钟行为或格点分配偏置。结论停留在“现有固定格点有诊断歧义，需校准”。后续若恢复实时调度验收，应同时记录 timer 每周期预期释放、实际触发与所用时钟关系，再比较固定格点和真实 timer 语义；本轮不追加硬件测试。

分析器已补充运行期相位检查：保存早于 expected 且超过锚点宽度的 start/finish 数量，以及全部负完成相位数量；发现矛盾时将 `runtime_phase_reference_valid` 与 `deadline_acceptance_available` 标为 false，保留 1,842 / 1 / 393 等原始格点统计，并将证据范围标为 `diagnostic_only_runtime_phase_conflict`。这种语义限制不改变本轮记录完整、`integrity.complete=true` 的判断。该补丁只涉及分析语义，不修改 state 行为或重做硬件测量；正常锚定与误差界内提前的合成样本仍可保留参考有效性。
