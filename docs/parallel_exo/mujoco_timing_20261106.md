# 当前 MuJoCo 动力学接口性能实测（2026-11-06）

当前接口在 200 Hz、120 s 的测试中完成 24,000 次调用，零超期、零跳周期；500 Hz、120 s 出现 3 次超过 2 ms 截止期，随后跳过 3 个释放点。200 Hz 可作为下一步控制集成的开发目标。

用户在 IMU 测量期间要求“直接测 mujoco”。本轮随后切换为当前正式控制仓库的独立 MuJoCo 接口测试，未继续 IMU + 模型联合长测。测量不打开 Viewer，不读取 IMU、不启动 ROS 状态或电机节点。

## 被测对象和方法

- Orin 开发副本：`/home/nvidia/parallel_exo_ros_framework/dev/jetson_mech_control`。
- 模型与接口：`mujoco/ref01/ref01_dynamics_api.py`、`config/mujoco/ref01_dynamics_cad_v1.xml` 及依赖。
- 同步 stamp：`3c741bbd185a93cb17bc03760d264d20ec9df06cdbd52462beee26f2b5d57188`，基于 Git `35c8babfbf0cbcc131bba9229d4148b0fbbeaf8c` 的未提交开发工作树。
- 使用已有 Orin MuJoCo 虚拟环境。每个 worker 只构建一个 REF01Dynamics 实例，先预热，再计时；模型装载与预热不计入单次耗时。
- 1024 个固定随机输入：psi 在 -44～44°，beta 在 1～44°；动态速度 -0.8～0.8 rad/s、加速度 -2～2 rad/s²。随机种子 20261103。
- micro：动态逆解、动态正解、零速度逆解、零速度正解各 5000 次连续调用。
- periodic：每周期执行一次完整动态逆解，以绝对释放时刻运行，过期释放点直接跳过，分别按 200 Hz（5 ms）、500 Hz（2 ms）各 120 s 测量。
- 保留逐调用原始 `timings.npz`、统计 JSON、每 200 ms 的外部资源采样和 tegrastats。未修改 CPU governor、电源模式、调度优先级或亲和性；GC 保持开启。

## Windows 先验证，再到 Orin

当前模型在 Windows 完成 100 组正逆解一致性、独立 KKT 方程、75 个冻结轨迹样本、非法输入拒绝及 50 ms 原生步进检查；结果通过。正逆解最大误差 1.43e-14 rad/s²，独立 KKT 最大误差 5.11e-14 rad/s²，原生步进闭环残差约 5.01e-7 m。

性能脚本基于本项目历史 `Mujoco-Win/tools/benchmark_ref01_orin.py`，来源 SHA256：`197d590c49f11644003a8c5a8e1213d50f003d461cd23941b55d8fd9f52d50b4`。本次仅适配正式仓库路径、输入哈希和自身子进程清理，并将执行状态改为 `COMPLETED`，避免将“执行结束”误称为实时性通过。模型和动力学算法未修改。路径保护、周期跳过及清理逻辑的 10 项测试在 Windows 与 Orin 均通过。

## 周期结果

两档均调用动态逆动力学，单位 ms。“释放到完成”包含唤醒等待及完整接口计算；每周期只调用一次。

| 频率 | 项目 | P50 | P95 | P99 | P99.9 | 最大 |
|---|---|---:|---:|---:|---:|---:|
| 200 Hz | 计算 | 1.460 | 1.593 | 1.664 | 1.787 | 2.132 |
| 200 Hz | 唤醒迟到 | 0.088 | 0.092 | 0.116 | 0.173 | 0.492 |
| 200 Hz | 释放到完成 | 1.548 | 1.683 | 1.752 | 1.915 | **2.207** |
| 500 Hz | 计算 | 1.413 | 1.470 | 1.517 | 1.675 | 1.945 |
| 500 Hz | 唤醒迟到 | 0.087 | 0.091 | 0.094 | 0.120 | 0.368 |
| 500 Hz | 释放到完成 | 1.500 | 1.558 | 1.606 | 1.785 | **2.156** |

| 频率 | 计划 / 实际调用 | 超期调用 | 跳过释放点 | 单核平均 CPU | 峰值 RSS | major faults |
|---|---:|---:|---:|---:|---:|---:|
| 200 Hz | 24,000 / 24,000 | 0 | 0 | 30.04% | 336.93 MiB | 0 |
| 500 Hz | 60,000 / 59,997 | 3 | 3 | 72.92% | 336.93 MiB | 2 |

500 Hz 超期调用占实际调用约 0.005%；超期调用和随后跳过的释放点是两个指标，不能相加作为同一种失效次数。2 次 major page faults 没有逐事件时间记录，不能据此认定它们造成了超期。

连续调用的计算时间约 0.7 ms，而周期运行计算约 1.4～1.5 ms。测试保留 schedutil 动态调频与普通调度，未做锁频因果对照，因此不把差异唯一归因于某一因素，也不使用连续调用结果代替周期预算。

本轮在 200 Hz 的最慢观测值与 5 ms 周期之间相差约 2.79 ms；这一差值只是本轮实测余量，后续还需计入 ROS 状态获取、控制律及电机通信。500 Hz 尚未达到本次“零超期、零跳周期”的目标。

## 复现入口

正式仓库 `tools/project/benchmark_mujoco_orin.py`。先通过 `tools/project/Sync-Orin.ps1 sync` 同步已在 Windows 验证的工作树，在 Orin 的上述开发目录执行：

```bash
py=/home/nvidia/parallel_exo_ros_framework/output/mujoco-venv/bin/python
"$py" -I -B -X utf8 tools/project/benchmark_mujoco_orin.py \
  --release "$PWD/mujoco/ref01" \
  --output "$PWD/.local/validation/<全新运行名>" \
  --label headless_periodic --mode periodic --rates 200 500 --seconds 120
```

输出目录必须全新，不覆盖历史记录。micro 单测使用另一个全新目录，参数为 `--mode micro --count 5000`。

本次测的是完整 REF01 理想闭链动力学接口，包含运动学映射、MuJoCo 模型计算、约束投影和小矩阵求解。没有测量控制器、ROS 通信、IMU、电机通信或 MPC 优化器，不将其表述为整机控制周期验收。
