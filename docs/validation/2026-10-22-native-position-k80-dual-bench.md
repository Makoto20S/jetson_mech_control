# Kp80双机同时台架测试（2026-10-22）

## 结果

用户明确授权两台同时运动，并确认离体固定空载、无人体连接、无干涉、可立即断电，
接线／板版本／CAN速率／方向单位不变。一次测试启动后约2.9秒因1号反馈力矩保护停止整组，
未完成正偏移及返回，双机位置验收未通过。未重试、未加力、未放宽保护。

之后退出manager，独立查询两台均status0（失能）：位置−2.092584／−1.124399rad，
速度−0.002442／+0.002442rad/s。端口关闭且无人占用，授权已消费，物理启动再次被阻止。
设备量纲沿用当前DM4340 profile声明，反馈力矩不是独立校准的测力结果。

## 配置和验证

使用与[上一轮单轴](2026-10-22-native-position-k80-bench.md)相同的原生MIT Kp80／Kd4，
名义速度参考和力矩前馈0；这次用户明确选择直接双机同时诊断，
并没有把上轮失败的单轴精度判为通过，也不是自动跳到后续阶段。

两轴各从本轮独立读回的静止位置出发：−2.103647／−1.130884rad；
目标各+0.03rad，参考斜率0.008rad/s，计划原位1s→偏移6s→返回6s。
每轴相对位移±0.2rad、反馈速度0.2rad/s、反馈力矩4N·m、目标偏差0.035rad，
任一保护异常停整组；末0.5s误差≤0.005rad且速度≤0.05rad/s的精度门限保留。
4N·m是反馈保护，非电机内部硬力矩限幅；名义PD配置预算为3.6N·m。
未改寄存器、Flash、超时或部署默认值。

本轮仅改仓库外测试脚本的执行组为`(0,1)`，生产源码及隔离安装未改变。
候选开关false、双机唯一执行组、两轴增益／参考限速／预算和记录容量断言、Python语法检查通过。
CompositeSystem双机预演通过：总elapsed15.061292s（含启动等待），6510条观察，
两轴端点均通过。这仅证明脚本和理想回环流程，不代表真实动力学。
生产代码沿用上轮已完成的构建和bringup310项软件测试，本轮未重复全量测试。

## 首故障与实际发送证据

真实脚本elapsed2.936472s，1426条ROS观察，处于`positive_0.03`阶段，未进入返回。
首个下层拒绝反馈如下：

| 字段 | 读到的值 |
| --- | --- |
| 轴／CAN／状态 | motor1、反馈CAN0、status1 |
| 原因 | torque，torque_exceeded=1、velocity_exceeded=0 |
| 位置 | −2.0975433rad |
| 速度 | 0.0561660562rad/s |
| 反馈力矩 | **4.43760684N·m > 4N·m** |
| 到达年龄 | 2656ns |

ROS状态不发布被拒绝的控制样本，故ROS接受记录中的力矩峰值较小：
1号0.676923、2号0.827350N·m；接受记录的速度峰值0.095238／0.129426rad/s。
不能用较小的ROS峰值否定首个拒绝反馈，也不能据此证明真实轴力矩发生相同幅度的跃变。
控制器释放请求被已故障的硬件拒绝；后续硬件停用、退出及独立两台失能读回完成，
不以controller标签代替真实设备状态。

有界快照封存完整：9217条、丢失0，串口写入无失败，CDC长度与CRC检查通过。
每轴实际1404条普通位置MIT帧，编码Kp79.975580／Kd4、速度参考−0.002442、前馈−0.006838。
故障后每轴另有1条Kp0／Kd4阻尼停机帧，随后失能；该帧的位置字段接近0，
因Kp0不产生位置弹簧作用，不能把它解释为运动中突然要求回编码器0位。

故障前最后实际写入的位置参考分别−2.089532311／−1.116769665rad，
仍在参考斜坡中。用1号最后位置帧和拒绝反馈的q/v估算PD约+0.399414N·m，
与拒绝帧的4.437607N·m反馈差异较大。该估算不是电机内部同步运算或校准测力，
不能仅凭差异断言机构卡住、驱动过流、错轴或串口解码错误。
本轮有TX及首拒绝字段，没有故障原始RX字节／设备内部电流独立证据。
下一步先补充有界原始RX取证并核对帧路由、解析及设备力矩含义，再评审运动复测；
不直接提高4N·m保护阈值。
