# 外骨骼架构验证记录（2026-10-16）

## 结论

目前验证了两条独立链路：ROS 2 双 IMU 接收及足底压力字段的软件处理链，以及达妙 DM4340 的 ROS 2 实机速度控制链。**鞋垫尚未接入，足底压力采集未做实机验证。整套外骨骼闭环也尚未验证通过**：当前没有订阅膝角/足底压力并生成电机目标的运行节点；双 IMU 标定、关节机械映射及穿戴负载试验也尚无实测证据。不要把离体电机轴运动写成外骨骼助力控制验证。

## 实际数据流与缺口

```text
STM32/CAN -> mech_ctrboard_bridge -> imu/imu1/data, imu/imu2/data
                                  -> fsr/left/*, fsr/right/*
双 IMU -> mech_knee_kinematics -> knee/flexion_deg, knee/joint_state
                                               [无运行中的控制策略连接]
外部测试目标 -> dm4340_velocity_controller -> dm4340_system -> USB-CAN -> DM4340
```

`mech_knee_kinematics.offline_loop` 是无 CAN、无电机话题的虚拟被控对象测试，不是实机控制器。它增加了合成足底压力门控，但足底压力尚未进入运行中的 ROS 控制策略。`knee/joint_state` 的关节名是 `knee_joint`，电机反馈名是 `dm4340_joint`；两者之间没有经过标定的方向、比例或零位映射。

仿真中无助力 RMSE 为 27.042 度，压力门控助力 RMSE 为 20.971 度；离地窗口 50/50 个样本输出为 0，压力输入失效后最大输出为 0 Nm。这些数值只描述合成轨迹和简化单自由度模型，不能推断人体助力效果、关节精度或安全力矩。

固件源码中的 `ExoTelemetry_Push()` 每约 100 ms 组装 196 字节传感器载荷，`comm_send()` 通过 CAN1 发送 ID `0x621` 的 Classic CAN 帧；CAN1 和桥均配置为 1 Mbps。启动后的第一段观察窗口曾为 0 帧，后续在未修改软件配置的情况下恢复；本次无法确定最初零帧的原因，不能据此判定某项接线或配置故障。实时读取到 I1 欧拉角约 `(179.8,-0.8,0.0)` 度、I2 约 `(-0.2,0.8,360.0)` 度；两侧足底总压力当时均为 0。Euler 数值受安装朝向和角度包裹影响，尚不是解剖学膝角验证。

原始 ROS 录包位于 Jetson 的 `/home/nvidia/ctrboard_system_validation_20261016/sensor_live_20261016`，共 11.263 秒、1188 条消息；数据库 SHA-256 为 `ff4bd3cd1d5d346f6da082a30901a43a1d2e93a5e0d93a965cae0e5f3ef1584f`。两路 IMU 数据与欧拉角各 113 条，左右足底原始点和总压力各 113 条，诊断 58 条。录包证明话题持续发布，不证明鞋垫已有非零受压响应或双 IMU 的真实角度精度。

**压力数据更正：**用户确认本次鞋垫没有接入。录包中的左右压力零值只是固件发送的占位字段，不能称为静止压力测量；上文足底话题消息数仅证明协议传输和 ROS 发布，不证明传感器工作。
