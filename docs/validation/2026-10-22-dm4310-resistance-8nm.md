## 抖动频率调查：50 Hz计算与500 Hz发送不同

用户提出控制频率疑问后查到：robot_node.py固定create_timer(0.02, self._tick)，
阻力策略计算/目标发布只有标称50 Hz；控制器管理器及底层发送标称500 Hz。
不能将重复发送上一条目标的500 Hz当成500 Hz抗阻计算闭环。

对20秒成功transport_result的单调时钟时间戳统计：

| 项目 | 1号 | 2号 |
| --- | --- | --- |
| 平均发送频率 | 500.054 Hz | 500.054 Hz |
| 周期中位数 | 1.999798 ms | 2.000005 ms |
| 周期99分位 | 2.060071 ms | 2.060967 ms |
| 最大周期 | 2.113642 ms | 2.113449 ms |
| 大于4 ms间隔 | 0 | 0 |
| 非重复力矩编码变化间隔中位数 | 20.001942 ms | 20.005718 ms |

编码变化还受动作和量化影响，不是每次应用tick的直接测量；但与源码20 ms计算周期相符。
本轮发送路径没有明显长停顿，不能归咎于发包频率不足；50 Hz计算导致的阶梯和采样滞后
是明确的架构短板，可能贡献抖动，仍不能证明它是唯一原因。
Linux实时FIFO调度申请被拒绝的警告存在，但本次发送统计未显示明显周期失控；未改系统权限。

下一步应优先设计通用C++阻尼快环，在控制器更新周期用最新轴速度计算、滤波及限幅，
上层保留模式、参数和启停监督；保持厂商适配边界，不只把Python定时器标为500 Hz。
该快环尚未实现和验证，不能声称提高频率已消除抖动。保护和人体禁用边界保持。
