# EXO-ARCH-001-TQ：双达妙输出限幅与反馈保护闭合

- 日期：2026-10-22
- 所属任务：EXO-ARCH-001
- 范围：两台达妙、一个共享网关、保留原生MIT位置控制。
- 目标：两轴各自以输出轴±8N·m作为请求上限；这是待核实的需求，尚未写入驱动器或认证为机构安全值。
- 状态：任务定义与代码审计完成；驱动器限幅接入、反馈异常定位及实机验收待完成。

## 1. 当前事实与缺口

[双机Kp80测试](../validation/2026-10-22-native-position-k80-dual-bench.md)在约2.94s因1号反馈
4.437607N·m超过4N·m保护而停止；没有完成返回，两台最终独立失能。
最后位置帧结合拒绝反馈的q/v估算PD约0.399414N·m，差异未定位。
不能通过升阈值或删除检测将该试验判为通过。

| 层次 | 当前代码 | 当前能力 | 缺口／本任务结果 |
| --- | --- | --- | --- |
| 策略监督 | `robot/supervisor.py:149` | 对effort命令按`max_command`饱和，再做斜率和位置保护 | 原生position台架不经过effort计算，不能靠此限制驱动器内部PD |
| 通用控制器 | `SingleJointCommandController` | 所选接口的minimum/maximum及变化率限制 | position接口限制的是位置，不得将8N·m写成位置上限 |

| 原生MIT驱动 | 发送q/v/Kp/Kd/前馈 | 内部算PD；Jetson没有独立总力矩上限字段 | 核实所接固件的驱动电流饱和能力、支持模式和读回途径 |

原生MIT总力矩上限。已确认内容与未知项见[位置阻抗说明](../development/dm4340_position_impedance.md)。
原生MIT若确实不支持独立输出限幅，应明确该模式无法满足此目标，再评审新模式／驱动方案；
不自动切换模式或恢复已移除的主机阻抗。

## 2. 分层参数和动作

下表为目标契约，不是已存在的新配置项。新增字段命名在实现时随接口评审确定。

| 参数／证据 | 请求值或状态 | 单位／坐标 | 作用与动作 |
| --- | --- | --- | --- |
| 两轴输出目标上限 | 每轴8，尚未生效 | 输出轴N·m，对称± | 驱动侧限制其产生的正负驱动力矩，达到上限保持受限工作，不以普通饱和本身触发故障 |
| 主机命令上限 | 待与驱动有效值联动，不能大于后者 | 所控关节N·m | effort路径先饱和，绕过上层时runtime仍饱和；绕过runtime的session内部超限拒绝；原生position不伪造该路径能力 |
| 驱动电流上限／基准 | 未知 | 厂商定义的A或标幺 | 必须核实相电流/Iq、峰值/RMS、基准和适用模式，不能由名称推断 |
| 电流→输出力矩映射 | 未知 | 电机轴→输出轴 | 核实Kt、减速比、标定与适用工况；系数必须有来源，不直接假设8A=8N·m |
| 反馈停机阈值 | 新离线双机候选8；上次运行配置4 | 当前底层为原始电机估计N·m | 超限整组停止并锁存；不得把请求8直接覆盖这里后称输出限幅生效 |
| 机构／人员允许范围 | 未知 | 对应实际机构 | 对命令、反馈阈值和试验包络施加更严格约束；8不得自动视作穿戴许可 |
| 饱和次数／持续时间 | 仅拟新增诊断，无既定停机秒数 | 次／s | 先观测限幅工作情况，持续饱和的发热／堵转保护另有依据后设计 |
| 故障锁存／恢复 | 保留，恢复需显式操作 | 整组 | 不自动重启；重新采集反馈、确认设备状态，不重放故障前目标 |

配置比较必须先统一到相同轴、单位、正负方向和估计量定义。
当前源码中effort映射到电机侧为`tau_motor=tau_joint*scale`，反馈返回为除以scale，
应覆盖非1及负scale的校验；不得把电机侧反馈阈值直接当输出轴阈值。

“输出限幅值”和“反馈停机值”不是同一个物理承诺：电流限幅限制驱动产生的力矩，
不限制外力作用、碰撞或全部传动载荷；反馈可能是估计量，存在量化、延迟和误差。
若反馈用于判断自身输出超过有效驱动限制，需要基于这些证据设计可解释的余量；
不能机械要求所有安全阈值都高于8，也不能无依据定成10或12。
如果结构允许值小于8，应降低正常输出目标而不是提高安全阈值。

## 4. 软件与硬件验收矩阵

| 检查 | 期望结果 |
| --- | --- |
| 未实现独立限幅却请求启用8N·m受限运行 | 明确拒绝新配置，指出缺失能力；不是降低诊断级别后继续 |
| 两台ID／读回混用、固件／模式改变、只一台读回成功 | 不允许整组按新限幅配置进入运行 |
| NaN／Inf／非正上限／非法枚举／缺失单位 | 配置期拒绝，串口构造和使能前发现能在离线发现的问题 |
| 主机effort命令超上限 | 正常策略及runtime对有限值截断；内部session仍拒绝越界，NaN/Inf和过期仍故障 |
| 正常电流饱和 | 受限工作并报告诊断，不把“达到上限”直接等同异常停机 |
| 反馈超限、无效帧、错误轴、断流／过期 | 按对应独立保护停组，保留首故障，不自动重启 |
| 上下限不一致 | 同坐标检查并提供可解释原因；不只对position前馈做截断 |
| 人工修改TMAX或OC_Value代替限流 | 无相应固件依据与量纲验证不接受为限幅证据 |
| 双机运行／单轴故障 | 每轴上限独立执行、任一故障停整组，两台独立查失能 |
| 声称物理力矩≤8 | 需要定义测量坐标、仪器／标定、误差及适用工况；控制帧／电机估计反馈不足以单独证明 |

当前没有独立测力验收能力证据，不能通过人为堵转、徒手抓轴或人体连接来替代测量方案。
台架首次验证应采用可控的小包络，不从需求值8自动推导一次8N·m加载试验。
RAM写入、Flash保存及电机运动分别明确范围；未知寄存器不盲写，Flash不默认保存。
