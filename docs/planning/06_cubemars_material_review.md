## 1. 审查结论

**用户确认事实**：当前两台定制电机的基础机型已经从“仅知 AKE60 系列”收敛为 **AKE60-8**。供应商资料库把标准目录项写作 `AKE60-8 KV80`，但不能仅凭目录名进一步断言定制实机仍使用标准 KV、绕组、减速器参数、驱动板固件或控制参数。

**用户确认事实（2026-09-01，取代 2026-08-19 的相反确认）**：本项目电机的适用协议手册是 **L07** —— `company/ak-series-prodcut-manual-v3-2-0-for-ak-3-0-robotic-actuator-cn.pdf`（AK3.0 V3.2.0，52 页）。它明确列出 AKE60-8，并覆盖伺服与力控两套扩展帧协议、状态反馈、CubeMarsTool 配置与参数导出。详见 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md)。

**与该确认相互独立的客观证据**：L02 覆盖的驱动板是 `AK-DRV-V2.1/V2.2/V1.0`，L07 覆盖的是 `AK54-4810-1C-A2` 等。登记资产 L14 表明本项目电机的驱动板正是 `AK54-4810-1C-A2`，它只出现在 L07。二者是**两代不同硬件**，不是同一手册的两个版本。这同时解释了本文档此前的一个疑点：L02 的运控/MIT 型号参数表里没有 AKE60-8。

> ⚠️ **~~用户确认事实（2026-08-19）~~ 已作废。** 原文称 L02（`ak-series-driver-manual-v1-0-18-for-ak-2-0-robotic-actuator-cn.pdf`）的 CAN 协议与当前电机一致，并据此把 L02 定为首要实现依据、把本文件 §4.6/§4.7 的 AK3.0 内容降为「补充」。该定位已于 2026-09-01 整体反转。**L02 不再是任何协议判断的依据。**

**规划决定（2026-09-01 修订）**：现有资料足以开始离线设计和单元测试 AK3.0 的**力控**（控制模式 ID `8`）与**伺服扩展帧**（控制模式 `0–6,15,16`）两个 codec；**先实现力控，再实现伺服**——该顺序推翻了先前基于 L02 的相反排序，理由是力控为阻抗控制，不具有伺服位置模式「以最大转速和加速度到达期望位置」的冲击风险。两者共享 canonical state/command 和 session 边界，但不共享会混淆帧类型、ID 或位域的打包函数。实机接入前仍须取得每台电机的只读配置、固件版本、active profile 和双编码器 CAN 字段来源。

### 4.2 双编码器

**资料事实**：AK V3.2 第 7 页把内环编码器写为 `21 bit` 单圈绝对值；双编码器型号的外环编码器为可选 `15 bit` 单圈绝对值。AKA V3.0 提供了相同的内/外环命名，可作为 CubeMars 双编码器通用旁证。

**资料事实**：AK V3.2 的 UART 参数响应同时包含“电机外环位置值”“编码器角度”和“外编码器角度”，说明固件数据模型能够区分外环位置与两个编码器相关字段。

**证据边界**：当前手册没有明确说明 CAN `0x29` 或可选 `0x2A` 的位置到底来自内环编码器、外环编码器还是固件融合值，也没有证明 CAN 能同时直接上传两个编码器值。因此不能先行决定 `joint/position` 的来源，更不能把两编码器角差直接解释为力矩。

**资料矛盾（2026-08-23 深读发现）**：L02 V1.0.18 第 7~9 页产品规格表写编码器为 **14-bit 单圈绝对值**，与 AK V3.2 双编码器资料的 21-bit 内环 / 可选 15-bit 外环不一致。两份手册描述的可能是不同代硬件；定制双编码器实机以哪套规格为准必须逐台确认（已列入 [05 §5.1](05_decisions_and_open_questions.md) 供应商问题清单第 3 条）。另注意 L02 第 31 页：原点设置命令 `Data[0]=1`（设置永久零点）**仅限双编码器机型**；单/双编码器机型对该命令的行为差异未在手册中说明。

### 4.3 CubeMarsTool 与实机配置

AK V3.2 第 15–17 页说明 CubeMarsTool 可以：

- 读取和写入电机、编码器参数；
- 配置 CAN 周期回报/问答模式、CAN 位速率、反馈速率和 CAN ID；
- 导出 `.AppParams` 与 `.McParams` 参数文件。

**规划决定**：首次实机核对只执行连接、版本读取、参数读取、截图和导出，不执行“电机参数识别”“编码器参数识别”“写入参数”“恢复默认”或固件升级。识别流程会驱动电机旋转，不属于只读证据获取。

### 4.4 L02 V1.0.18 CAN 命令族（**历史记录，2026-09-01 起不再是实现基线**）

> ⚠️ 本节整节按 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md) 降级为历史。L02 是 AK2.0 驱动器手册，覆盖 `AK-DRV-V2.x` 驱动板，与本项目的 `AK54-4810-1C-A2` 不符。**当前实现基线见 §4.6/§4.7。**
>
> 内容保留的价值有二：一是记录基线切换前的判断依据，二是两代对照本身有用——L02 的伺服标度与 L07 逐条相同（位置 `×10000`、电流 `×1000`、转速原值、`0x29` 布局一致），但 L02 的运控/MIT 是 **11 位标准帧**且位序为 `位置 速度 Kp Kd 力矩`，而 L07 力控是 **29 位扩展帧**且位序为 `Kp Kd 位置 速度 力矩`。**任何把两者混用的打包函数都会静默产生错帧。**

#### 4.4.1 伺服模式：29 位扩展帧（历史；标度与 L07 相同，引证须改用 L07）

L02 第 27~40 页规定伺服命令使用 29 位扩展帧：扩展 ID 的 bits[28:8] 为控制模式（功能 ID），bits[7:0] 为电机 ID。命令族（功能 ID）：0 占空比、1 电流环、2 电流刹车、3 转速、4 位置、5 设置原点、6 位置速度环；数据均为大端。关键缩放（2026-08-23 深读，第 28~32 页）：电流 `int32/1000` [A]（±60 A 编码范围）、位置 `int32/10000` [°]（±36000°）、位置速度环 8 字节 = 位置 int32/10000 + 速度 int16/10 + 加速度 int16/10。

反馈（第 32~33 页，人工复核）：**定时上传模式，上传频率可配置 1~500 Hz**；`0x29` 为 8 字节实时状态：位置 `int16/10` [°]（±3200°）、速度 `int16×10` 电气转速、电流 `int16/100` [A]、驱动板温度 `int8`（-20~127 ℃）、报错代码 `uint8`。故障码表（第 33 页）：0 无故障、1 电机过温、2 过流、3 过压、4 欠压、5 编码器故障、6 MOS 管过温、7 电机堵转。

**codec 必须处理的附加帧**（此前未记录）：功能 ID `0x09` 表示电机处于跳转引导状态；`0x2C` 为电机进入伺服模式的起始帧，回复固定 `0xFA 0xFB 0xFC 0xFD`。注意 `0x29` 反馈位置（int16，±3200°）与位置命令（int32，±36000°）分辨率/量程不对称。命令和反馈的 ID、DLC、字节序、缩放与错误码必须形成 golden/negative vectors。

#### 4.4.2 运控/MIT 模式：11 位标准帧（第二实现目标）

L02 第 41~45 页规定运控/MIT 使用 11 位标准帧和 8 字节 payload：接收帧标识符 = 电机 ID（默认 1），反馈帧标识符 = `0x00 + 驱动器 ID`。进入控制以末尾 `0xFC`（第 41 页原文加粗警告"使用 CAN 通信控制电机时必须先进入电机控制模式！"），退出以 `0xFD`，设置零位以 `0xFE`；普通命令按 position[16] / velocity[12] / Kp[12] / Kd[12] / torque[12] 位打包，反馈包含驱动器 ID、位置[16]、速度[12]、扭矩[12]、温度（`T_int-40`）和错误标志（该字节的故障码表手册**未给出**）。该 profile 不能因为"看起来像 MIT"而复用第三方旧 codec，必须按 L02 的范围、位域和标准帧 ID 单独实现。

**⚠ 归一化常量陷阱（2026-08-23 深读发现，安全相关）**：第 43 页示例代码用固定常量做位打包归一化——`P ±12.5 rad`、`V ±30 rad/s`、`T ±18 N·m`、`Kp 0~500`、`Kd 0~5`——而第 42 页"参数范围"表按型号给出的物理极限差异巨大（如 AK10-9 扭矩 ±65 N·m、AK80-64 ±144 N·m），示例代码并不按型号切换常量。**且第 42 页型号表（10 个型号）不含 AKE60-8**。定制实机固件在 MIT 编解码时实际使用哪套 MIN/MAX 常量必须先确认（[05 §5.1](05_decisions_and_open_questions.md) 问题 2/3），否则扭矩编码会产生系统性错误；MIT codec 的归一化常量必须来自逐台设备配置，禁止硬编码手册示例值。

L02 第 4 页注意事项第 4 条明确警告（2026-08-23 人工复核原文）："多种可选控制方式在驱动板运行时不可切换，且不同控制方式之间通信协议不同。如需切换，请重新启动电源，然后再进行更改。使用错误的协议控制可能会使驱动板烧毁！" 因此"支持两种"表示配置层可选择两种独立 profile，不表示 ACTIVE 时自动探测、混发或热切换；切换只能在停用、断能/neutral、重新 configure 并通过相应证据闸门后发生——且按手册要求需要重新上电。

#### 4.4.3 失控保护与固件升级（2026-08-23 新增）

- **失控保护**：第 18 页"应用功能"页面（原文："该页面主要为 CAN ID 设置、CAN 通讯速率以及 CAN 通讯突然中断的设置"）提供 `失控时间(ms)` 与 `失控刹车电流(A)` 两个参数——即命令中断看门狗机制**存在**，超时后以设定电流刹车。截图中两字段均为 0（疑似默认不启用）；出厂默认值、启用状态、取值范围与能否经 CAN 报文配置手册均未说明。协议正文没有对应的 CAN 设置报文，工程上大概率只能用 CubeMarsTool 逐台预配置。该参数属于 G0 必读项与 G3 前必配项。
- **固件升级**：第 25~26 页说明升级流程；红字警告"如果您的固件包含了伺服和 MIT 两种固件，请分别上传这两个固件，以确保两种模式的正常使用"——G0 固件取证时必须同时记录两个 .bin 的版本。
- **CAN ID/波特率修改**：仅见上位机界面路径（第 18 页），协议未定义修改 ID/波特率的 CAN 报文。

### 4.5 HighTorque USB CDC transport 参考边界

`hightorque_fdcan` 更像通信板的 transport 示例，而不是电机 SDK。源码观察到：

- `MODE_FDCAN_PASS (0x12)`；USB CDC 外层帧头、CRC8/CRC16 和批量 payload；
- 每条原始帧带 CAN ID、标准/扩展标志、Classic CAN/CAN-FD、BRS、长度和最多 64 字节数据；
- 默认扫描 `/dev/ttyACM*`、USB VID/PID `0xCAF1:0xFFFF`、串口 4,000,000 baud，并要求通信板版本至少 `4.8.8`；
- 示例没有完整 nominal/data bitrate 配置、硬件时间戳或错误帧 API；构造函数立即打开串口、查询版本，失败时 `exit(1)`。

因此项目只提炼一个可注入、可失败、由 `BusRuntime` 拥有的 `HighTorqueUsbCdcTransport`；它与 `FakeTransport`、SocketCAN transport 共享 `RawCanFrame` 契约，不能把 CDC framing、串口线程或厂家 motor class 直接塞入 codec/SystemInterface。

### 4.6 AK3.0（L07）profile —— 当前协议基线

> 2026-09-01：本节原标题为「AK3.0 V3.2 补充 profile（非当前默认）」。按 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md)，**它现在是基线**，且**力控为第一实现 profile、伺服为第二**。

L07 使用 29 位扩展帧，扩展 ID 的低 8 位是 Drive ID，高 21 位是功能/控制模式 ID。Drive ID 只有 8 位，因此上位机显示的 CAN ID 必然是十进制，任何 ≥256 的读法都不可能。

| profile | 扩展 ID / 功能 ID | payload | 建议实现名 |
|---|---|---|---|
| **力控**（第一实现） | 控制模式 ID `8` | `Kp[12], Kd[12], position[16], velocity[12], torque[12]` | `CubemarsAkV3ForceCodec` |
| servo 占空比 | 功能 ID `0` | `int32(duty * 100000)`，4 字节 | `CubemarsAkV3ServoCodec` |
| servo 电流 | 功能 ID `1` | `int32(Iq[A] * 1000)`，4 字节 | 同上 |
| servo 电流刹车 | 功能 ID `2` | `int32(I[A] * 1000)`，4 字节 | 同上 |
| servo 速度 | 功能 ID `3` | `int32(ERPM)`，4 字节 | 同上 |
| servo 位置 | 功能 ID `4` | `int32(deg * 10000)`，4 字节 | 同上 |
| servo 设置原点 | 功能 ID `5` | 1 字节指令 | 同上 |
| servo 位置速度 | 功能 ID `6` | `int32(deg*10000)` + `int16(ERPM/10)` + `int16(acc/10)`，8 字节 | 同上 |
| servo 失能 | 功能 ID `15` | 无 payload | 同上 |
| 反馈设置 | 功能 ID `16` | 2 字节设置；写入 Flash | 配置工具，不进入周期路径 |

**力控三个子模式共用控制模式 ID `8`，由载荷内容区分**（只给位置+Kp+Kd、只给速度+Kd、只给扭矩），必须由同一 codec 按显式配置选择，不得按收到的数据反推。

**AKE60-8 力控归一化常数**（L07 第 37 页；位置与 Kp/Kd 为跨型号合并单元格，已按原页图确认而非 `pdftotext` 推测）：

| KV | 位置 | 扭矩系数 `Kt` | 速度 | 扭矩 | Kp | Kd |
|---:|---|---:|---|---|---|---|
| 80 | ±12.56 rad | **0.7382 N·m/A** | ±40.0 rad/s | ±15.0 N·m | 0–500 | 0–5 |

`T = Kt × Iq`，其中 **T 为输出端输出扭矩**。项目负责人 2026-09-01 担保该行适用于本定制版，据此 [ADR-009](../adr/ADR-009-effort-semantic-gate.md) 解除了「Kt 未知」这一阻塞项。

> ⚠️ **L07 §4.4.1 的力控速度环示例有误。** 该行给出 `00 06 66 7F FF 98 67 FF` 并标注「速度设置为 6rad/s」，但 `DATA[5]=0x98` 反解为 **5.3402 rad/s**；应为 `0x9B`，反解得 5.9966。同表其余示例（力矩 2 N·m → 1.99、4 N·m → 4.00、位置 6 rad → 6.029、Kp → 1.95、Kd → 2.00）全部精确吻合，正是这一点证明位打包与归一化无误而示例有误。**golden vector 必须逐条按文档化范围反算，不得照抄手册示例**——照抄该行会固化约 11% 的系统性速度误差，且离线测试无法发现。

**关键冲突**：旧 Arduino demo 的标准帧 MIT payload 顺序是 `position[16], velocity[12], Kp[12], Kd[12], torque[12]`，与 L07 力控的 `Kp, Kd, position, velocity, torque` 位序和帧类型都不同。上一代 L02 的运控/MIT 同样是 11 位标准帧且位序不同。三者必须是不同的 codec，禁止用运行时猜测或一个布尔开关共用打包函数。

**「无需切换」的证据与本项目的立场**：L07 第 4 页产品特色称 servo 与力控「使用无需进行切换」。该句挂在「对上位机 CubeMarTool 进行了全新升级」之下，与「控制界面更为简洁」并列，**主语是上位机工具**。旁证：L02 的上位机有「模式切换」页（引导/伺服/运控）而 L07 没有（§3 唯一的「切换」是中英文切换）；L07 §3.3 在同一台连接的电机上依次演示伺服与力控；§3.4 固件升级是单一下拉列表，没有 L02 §4.4「请分别上传伺服和 MIT 两个固件」的说法。因此**一份固件很可能同时接受两个命令族**。

即便如此，**本项目仍在 `on_configure` 固定控制 profile、ACTIVE 期间不混发**。按 ADR-013 第 5 条，该规则的理由已明确改写为**本项目的主动选择**（运行期在位置伺服与力控之间混发会使控制权归属、缩放、neutral 和故障归因失去确定语义），而不再是「固件做不到」。同时注意：L02 注意事项第 4 条那句「使用错误的协议控制可能会使驱动板烧毁」在 L07 中已不存在，但警告消失不等于证明切换安全，也可能只是文档简化，因此保守侧不变。

### 4.7 AK3.0 状态反馈（当前基线）

| 报文 | 资料定义 | 软件处理 |
|---|---|---|
| `0x2C` | 电机进入伺服模式时**由电机主动发出**的起始帧，固定回 `0xFA 0xFB 0xFC 0xFD` | 供 session 做状态转换；不解码为设备状态。伺服因此**不需要主机侧激活握手** |
| `0x29` | 扩展帧，8 字节，周期上传可配置 `1–2000 Hz` | 作为基础状态帧；保存源到达时间和 age |
| `0x29` 字段 | 位置 `int16`（0.1°）、ERPM `int16`（10 ERPM）、Iq `int16`（0.01 A）、驱动板温度 `int8`、故障码 `uint8` | codec 保留原始值，再按已确认极对数/减速比映射 SI |
| `0x29` 故障码 | `0` 无故障、`1` 电机过温、`2` 过流、`3` 过压、`4` 欠压、`5` 编码器故障、`6` MOS 过温、`7` 堵转 | 原始值必须原样保留在 `raw_fault_code` |
| `0x2A` | 可选额外位置扩展帧，前 4 字节为 `int32` 位置（0.01°） | 只有确有分辨率需求且预算通过才启用 |

L07 明确给出输出侧换算：**`输出端转速 = ERPM（电气转速）÷ 极对数 ÷ 减速比`**。位置字段没有对应的输出侧声明，手册在需要时会写明「输出端」（力矩处就写了），此处未写——因此 `0x29` 位置究竟取内环、外环还是融合值**仍未解决**，不得据此声明 `joint/position` 语义。

> ⚠️ **两个会让基于旧世代经验的解码器出错的陷阱：**
>
> 1. **`0x29` 的 `DATA[7] = 0x77` 是「失能成功」回执，不是故障码。** 发送功能 ID `15`（失能）后，电机会在 `0x29` 帧的 `DATA[7]` 赋值 `0x77` 并回传一次。故障码表只到 `7`，把 `0x77` 当故障码会把一次成功失能误报为未知故障——而失能恰恰是安全路径。
> 2. **单圈模式会改变位置语义。** 反馈设置（功能 ID `16`）的 bit[14] 打开后位置范围变为 `0°–359°`（多圈模式为 `±36000°`，即 ±100 圈），bit[15] 则额外发送 `0x2A`。**这些设置写入 Flash 且掉电保存**，即位置该如何解码取决于一个在线上看不见的设备端状态。configure 时必须显式声明并与实机读回核对。

反馈设置命令会写 Flash，不能在启动或周期循环中反复发送。`1–2000 Hz` 是协议可配置范围（L02 为 1–500 Hz，上限提高不构成天然约束），不等于 2000 Hz 控制闭环已经在当前 Jetson、当前总线和两台实机上通过时序测试；实际约束来自总线预算，见第 6 节。

### 4.8 标准 AKE60-8 力矩候选参数

AK V3.2 第 37 页给出的标准 AKE60-8 参数为：

| 参数 | 标准资料值 |
|---|---:|
| 位置范围 | `-12.56 .. 12.56 rad` |
| 速度范围 | `-40 .. 40 rad/s` |
| 扭矩范围 | `-15 .. 15 N*m` |
| 扭矩系数 | `0.7382 N*m/A` |

手册明确给出 `T = Kt * Iq`，并把 `T` 定义为“输出端输出扭矩”。这使标准 `joint/effort` 映射从“完全未知”收敛为“有标准机型候选”。但定制结构和双编码器版本是否保持同一 Kt、减速比、方向及固件参数仍须通过供应商确认或每台实机 `.McParams`/`.AppParams` 证据锁定，不能先硬编码 `0.7382`。

## 5. 对 500 Hz 与 1 kHz 的影响

以下沿用经典 CAN 最坏位填充预算：8 字节扩展帧按 160 bit，4 字节扩展帧按 120 bit，位速率假设为 1 Mbit/s。HI12 仍按每台 3 个 8 字节扩展帧、100 Hz 估算。

> **2026-09-01 按 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md) 重算。** 力控命令固定为 **8 字节扩展帧**（三个子模式共用同一布局），反馈仍按 `0x29` 8 字节扩展帧计。**因此力控的帧长与此前「8B 命令 + `0x29`」场景完全相同，切换基线并未使带宽变差**——这一点在切换前是未知的，重算的结论是不需要下调频率目标。

| 场景 | 最坏流量 | 总线占用 | 结论 |
|---|---:|---:|---|
| 力控 2 电机 @500 Hz，无 HI12 | 320 kbit/s | 32.0% | 电机协议预算充足 |
| **力控 2 电机 @500 Hz + 2 HI12 @100 Hz** | **416 kbit/s** | **41.6%** | **当前 500 Hz 单物理通道静态预算候选**；backend/时序仍待证 |
| 力控 2 电机 + `0x2A` @500 Hz + 2 HI12 | 536 kbit/s | 53.6% | **超过 50% 平均目标**；`0x2A` 在 500 Hz 下不得启用 |
| 力控 2 电机 @1 kHz + 2 HI12 | 736 kbit/s | 73.6% | 拒绝作为单总线配置 |
| 力控 6 电机 @200 Hz | 384 kbit/s | 38.4% | 六电机设计包络首选基线 |
| 力控 6 电机 @200 Hz + 2 HI12 | 480 kbit/s | 48.0% | 接近平均预算上限，需实测 |
| 力控 6 电机 @250 Hz | 480 kbit/s | 48.0% | 同上 |
| 力控 6 电机 @500 Hz | 960 kbit/s | 96.0% | 拒绝 |

**规划目标（受 [ADR-006](../adr/ADR-006-conditional-can0-deployment.md) Proposed 约束）**：两电机命令/反馈目标维持**最高 500 Hz**，六电机包络为 200–250 Hz。协议上限已由 L02 的 500 Hz 提高到 L07 的 2000 Hz，**因此频率上限不再由协议决定，而由总线预算决定**：1 kHz 两电机场景为 73.6%，明确拒绝。`0x2A` 只有在降低电机频率或迁至第二条总线后才可考虑。`controller_manager` 可独立支持 1 kHz 主机实验，不得据此提高电机 I/O 频率。静态预算不证明单总线拓扑、仲裁最坏响应或 USB transport 时序已可激活。

> **本节的一个未决项**：L07 §4.3.1 的标题是「**伺服模式**驱动板反馈数据定义」，§4.2 力控只定义了命令帧，手册**没有明确说明力控模式下的反馈帧是什么**。合理推断是 `0x29` 作为与命令族无关的周期状态帧（它由应用设置里的 CAN 口模式/反馈速率控制，而非按 profile 配置），但这是推断而非资料事实。对本节结论无影响——任何合理的反馈帧都是 8 字节扩展帧——但 codec 实现前应向供应商确认，已列入待确认项。

6. 驱动板或整机是否内置 120 Ω 终端电阻？若可切换，默认状态和配置方法是什么？

**正式供应商问题清单（可直接发送）已整理至 [05 §5.1](05_decisions_and_open_questions.md)。**对上述第 1、2 项，最直接的证据不是继续索要通用手册，而是分别保存两台实机的 CubeMarsTool 连接/版本截图、基础设置截图（含"应用功能"页失控保护参数），以及只读后导出的 `.AppParams` 和 `.McParams`。其余项若配置导出仍无法回答，再按 05 §5.1 清单发给 CubeMars 技术支持。

## 7. 对框架实现的约束

1. **（2026-09-01 按 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md) 改写）** `mech_protocol_cubemars` 区分 AK3.0 的 **力控**（控制模式 ID `8`，第一实现）与 **伺服扩展帧**（控制模式 `0–6,15,16`，第二实现）两个 profile，二者不得共用有歧义的打包函数。上一代 L02 的 `servo-extended` / `motion-control-MIT-standard` 组合**不再实现**：其 11 位标准帧 profile 在本项目硬件上不存在。
2. `DeviceSession` 绑定明确的协议代际、固件范围、Drive ID、反馈集合和编码器来源；ACTIVE 期间不自动识别或混发命令族。
3. `SystemInterface` 只暴露经 capability 证明的标准接口。若实际 CAN 位置来源未确认，`joint/position` 不得假定使用外编码器。
4. 极对数、减速比、方向、零位、反馈率来自每台设备配置，不在 codec 中按型号硬编码。**归一化 MIN/MAX 常量与 Kt 现在有了本项目适用手册中本型号自己的一行**（L07 第 37 页 AKE60-8：位置 ±12.56 rad、速度 ±40.0 rad/s、力矩 ±15.0 N·m、Kp 0–500、Kd 0–5、`Kt = 0.7382`），因此可以作为**该型号的默认值**注入，但仍须保留按台覆盖能力，且不得挪用其他型号的行。~~§4.4.2 陷阱「型号表不含 AKE60-8」~~ 是 L02 时代的问题，L07 包含本型号。
5. `0x2A` 与单圈模式由功能 ID `16` 配置、**写入 Flash 且掉电保存**；启用前必须进入总线预算核算，任何反馈设置/Flash 写操作都不得进入普通启动或控制循环。位置解码语义依赖该持久化设置，configure 时须显式声明并与实机读回核对。
6. 现有 C++ 控制器仍只依赖 `position`、`velocity`、`effort` 和质量/新鲜度契约。未来更换其他 CAN 电机时，只要新 adapter 提供相同接口语义，控制器无需修改。
