# AK3.0 位置伺服适配设计

日期：2026-09-28。任务：SERVO-001。状态：离线适配进行中；未部署、未做伺服实机验收。

## 目标与实施边界

首个目标为指定位置角度，并限制速度和加速度。使用固定的
`Ak30ServoExtended` profile 与功能 6；不使用默认最大速度/加速度的位置功能 4。
现有力控实现保持独立，控制器继续使用标准 `position` 接口。
第一版速度与加速度限制作为逐设备固定配置，不新增控制器命令接口，
不借用 `effort` 或 `command_generation` 字段传递加速度。

软件分为三个验收层次：

1. 纯协议编解码：设备原生角度、速度和加速度字段，黄金帧及非法输入验证。
2. 离线映射、设备状态与共享总线：显式合成映射的双设备 FakeTransport 验证。
3. ROS 组合与实机部署：在设备坐标、限位及中止行为有证据后推进；前两层通过不代表此层通过。

新电机 104/105 共用物理 CAN0，需由一个总线运行时统一接收和发送。
不能为每台电机分别打开同一个串口。设备 profile 固定于配置，ACTIVE 期间不混发力控/伺服指令。

## 协议依据与能力声明

依据 [ADR-013](../adr/ADR-013-ak30-protocol-baseline.md) 指定的 L07
AK3.0 V3.2.0 中文手册，印刷页 30、34–36、41–43。

| 内容 | 格式及限制 |
|---|---|
| 功能 6 | Classic CAN 扩展数据帧，ID `(6 << 8) | drive_id`，DLC 8；104/105 对应 `0x668/0x669` |
| 目标位置 | 有符号大端 int32，设备度数乘 10000，手册范围 ±36000°；缩放后 ±360000000 可由 int32 表示 |
| 速度上限 | 正的电气转速 ERPM 除 10，再截断为 int16；非零有效量化值 |
| 加速度上限 | 正的原始协议量除 10，再截断为 int16；手册印为 ERPM/s²，其物理单位解释待确认 |
| 常规反馈 | `(0x29 << 8) | drive_id`，DLC 8；位置 0.1°、速度 10 ERPM、电流 0.01 A、有符号温度、原始状态 |
| 失能功能 15 | DLC 0，反馈状态 `0x77` 表示失能成功；不是受控减速或静止证明 |

位置和上限均拒绝非有限数、越界数或量化后无效的值，不做静默裁剪。
反馈需检查设备 ID、逻辑总线、方向、帧格式和长度。故障、未知状态及失能确认
不可冒充正常可用的位置样本。不从反馈猜测当前控制模式或编码器来源。
功能 5 设置原点、功能 16 写 Flash、功能 0–4、`0x2A` 扩展反馈不属于首个实现范围。

## 坐标、限位和证据边界

NEW104/105 是替换后的新个体，不能继承旧 motor1 的零点、方向或实机验收。
目标角度转换与反馈角度转换必须分别声明，不能未经核验认定两者来自同一个编码器。
离线测试使用合成坐标配置，真实部署值保持未确认。

2026-09-28 手动摆动得到的成对原始设备角度为：

| 手动端点 | 104 | 105 |
|---|---:|---:|
| 左端 | -44.3° | 46.2° |
| 右端 | -273.5° | 261.3° |

这些值是单次观测参考，不是标定关节零点，也不是允许独立组合的矩形安全工作区。
机构耦合、重复性、断电后坐标、内缩余量仍需确认。不得直接作为可命令限位。

导出参数中的 `foc_encoder_ratio`、`si_motor_poles`、`motor_poles` 等字段不足以单独证明
极对数和伺服坐标换算。反馈 ERPM、电流不自动转换为已验证的关节速度或力矩。
在加速度量纲未明确前，接口命名保留原始协议单位，不伪称 rad/s² 限幅已获验证。

### 2026-09-28 资料复核补充

[厂家 AKE60-8 规格](https://www.cubemars.com/product/ake60-8-kv80-quasi-direct-drive-actuator.html)
明确给出14极对、8:1减速比，两台设备历史截图的 Pole Pairs=14、Ratio=8 与此一致。
因此在标准型号与ERPM语义成立时，输出轴角速度可按 `ERPM × 6 / (14 × 8)` °/s
换算；10 ERPM量化步长约对应0.535714°/s。这不是机构末端速度、位置坐标映射或
当前实机配置已通过验证的结论。`si_gear_ratio=0` 不可用于否定型号减速比。

L07 p19将通用UI位置称为转子位置，p43 UART又分别给出外环位置与内/外编码器角度，
不足以证明定制DE_V3.4的目标与CAN反馈共用输出轴坐标。p35将加速度写作ERPM/s²，
p46、p52 UART示例使用ERPM/s；p35非负加速度范围还与p51负向CAN示例矛盾。
上线前须确认量纲及反向动作的速度/加速度符号规则，不能将文档笔误猜测当结论。

两份App导出均有 `timeout_msec=1000`、`timeout_brake_current=0`；没有证据说明
mode6刷新该计时器或到期会清除轨迹/制动。两机电流环参数也不同：104的
Kp/Ki为0.01/10，105为0.119908/2505.11，截图与XML一致；开关频率分别20/35kHz。
这些是历史导出差异，不能判定哪台错误，不得互相复制，也不是上层力控命令增益。
先核实来源与当前加载值，再决定是否需要配置工作；本轮未改任何设备参数。

## 共享总线与失效处理设计

一个 `BusRuntime` 负责一条物理总线，逐设备维护反馈、授权、命令代数和有效期。
发送前必须处理收到的每一帧反馈，不能只看接收批次的最后一帧，否则先故障、后正常
可能掩盖应锁存的故障。路由先按设备和总线身份分发，再由会话检查帧形状，
不能在路由中滤掉匹配设备的异常帧。匹配的不可用反馈撤销已经准备的目标授权；
即使同批次后续收到正常反馈，也必须准备新命令，不能复活旧的待发送目标。
接收处理、设备检查、撤销无效目标、发送依次进行。

撤销某设备授权时清除该路尚未发送的目标；背压重试不能重放已过期或已撤销目标。
待发送帧在实际发送前还需复核最新反馈、量化目标的位置包络及原命令有效期，
成功准备过一次不代表可以在背压后无限重试。命令代数、截止时间和帧必须对应同一次准备。
双设备测试中允许健康设备继续，仅用于证明路由隔离；这不是耦合机构的实机故障策略。
实机组合必须另行确定任一电机故障时是否中止整组，以及中止的物理实现。
停止/恢复开启新生命周期时清除旧队列及旧反馈，并要求新反馈和新命令。
软件丢弃待发送命令只证明后续无目标帧，不证明驱动器内部轨迹停止。

功能 6 的重复目标、轨迹规划方式、设备超时、主机断联后的行为在 L07 中未充分定义。
因此不能把 [ADR-012](../adr/ADR-012-command-watchdog-and-capability-honesty.md)
的主机租约机制解释成设备停止保证，也不能把重复发送当前位置当作已证明的停止。
功能 15 仅单独提供显式协议编码；自动停机策略、重试和确认超时需另行明确，
不能仅凭一个 `0x77` 就宣布机构静止。

## 离线验收与实机前置条件

离线验收覆盖协议黄金帧、异常输入、显式坐标、ID 隔离、单总线所有权、反馈先于发送、
故障锁存、授权撤销、有效期、背压与重启不重放；现有力控/JTC 回归必须保持通过。
具体通过数量由实际测试报告给出，本设计不预先宣称通过。

真实部署前需要确认：

- DE_V3.4 的目标/反馈编码器来源、原点、方向、单圈/多圈行为和物理单位。
- 机构允许的目标组合，以及逐设备速度、加速度和位置内缩限值。
- 重复目标、目标中止、设备超时和失能后的实际响应及静止判据。
- 单总线带宽、反馈新鲜度、配置一致性与相应 G0–G3 条件。

首个实机动作将是有明确目标、限制和终止条件的独立测试；离线代码完成不授权运动、
修改原点、写 Flash 或升级持久部署。

## 2026-09-29 生产组合补齐

用户要求后续验收经过本仓库已有伺服实现。实际调用链为标准位置控制器 →
CompositeSystem → Ak30ServoRuntime → Ak30ServoPositionSession → BusRuntime →
UsbCdcTransport → CdcSerialPort；测试只在最后的传输/串口与时钟边界注入模拟对象，
不复制会话、发送授权或故障逻辑。

通用状态接口子集见 [ADR-020](../adr/ADR-020-declared-state-interfaces.md)（Proposed）。
Servo 只导出 position，原始 ERPM/Iq 保留在诊断快照。硬件声明 position 和
command_generation，标准控制器仅 claim position 时使用现有弱档契约。

每个组件只创建一个串口/transport/BusRuntime，多设备会话按 joint 顺序绑定，
各自 target/feedback affine 显式提供且互不推定。缺失或未知配置在打开设备前拒绝。
configure 不开启设备；activate 启动 bus/open 后初始化网关接收，首次循环前完成；
deactivate/error/cleanup 停止 bus 并关闭串口，重新激活重新初始化、重新等待反馈。
派生插件析构时先停 runtime，确保借用的 transport/serial 仍在有效生命周期内。

接收必须观察到队列排空边界后才发送；单批预算用尽不能当成接收完成。已建立
反馈的任一设备变为不可用时，组件清除所有主机待发目标并失败；单个 claim 释放
仅取消该设备待发目标。这个组件级中止不等于设备侧制动，也不自动发送失能、
归零或“保持当前位置”。总线逐帧发送不是双电机事务；中途失败只能撤销
尚未发送的帧，不能撤回先前已发送的目标。真实停止策略与首次实机动作仍单独确定。

命令有效期遵循 ADR-012 的 `hard > soft > 0`。尚未发送的目标在 soft
截止时丢弃并失败；已实际发送的目标在 soft 到 hard 之间停止刷新，到原 hard
截止时失败。接收预算未排空也不能延后看门狗；释放 claim 清除该路旧命令历史。
这里的等待阶段只是主机行为，不表示电机内部轨迹已暂停。

2026-09-29 断电对照及手动观察只验证了两台原始反馈和局部可动性；没有验证
mode6 命令坐标、机械加速度或停机。生产集成可先用显式合成映射离线/ARM64
验证，不必等待厂家答复；实机映射则通过后续明确范围的实验继续取证。
