# DESK-CTRL-001：桌面双 IMU 到单台达妙速度控制

## 本轮目标

用户选择先完成简单控制，在离体固定空载台架检验
`CtrBoard → 双 IMU 姿态 → 桌面策略 → 通用速度控制器 → 达妙适配 → 电机反馈`。
暂停架构拆分；不使用人体膝角、机械膝关节映射或高级步态算法。
本地开发，不提交 PR #34。

## 组成与控制律

新增 `mech_assist_control/desk_follow.py` 纯逻辑与 `desk_node.py` ROS 包装。
复用现有姿态、传感器诊断、通用 VelocityCommandController 和达妙硬件插件。
默认入口 `desk_imu_follow_node` 仅发布 `desk_imu_follow/preview_velocity`；
明确设置 `output_mode:=motor` 才建立真实目标话题发布者。
节点不打开串口、不启用硬件，不修改模式、CAN 或电机寄存器。

消费 `attitude/relative/orientation`。显式 arm 时记录当前相对姿态为桌面零位，
计算 `conj(q_zero)*q_relative` 绕标准 Y 的 twist；这不是人体膝角。
5° 死区外，`velocity = 0.8 * signed_remaining_angle_rad`，
限幅 ±0.3 rad/s、斜率 0.3 rad/s²；输入超过 ±30° 锁存故障。
不要将它解释为电机位置伺服；输入偏转保持时给持续速度，回到零位附近才归零。

| 检查 | 约束 |
|---|---|
| 输入及诊断新鲜度 | 300 ms，包时间戳必须新鲜且严格递增 |
| 电机反馈新鲜度 | 150 ms，时间戳严格递增 |
| arm | 初始 idle，双 IMU 有效；电机模式还须反馈有效且速度 ≤0.1 rad/s |
| 定时器中断 | 相邻控制 tick 超过 100 ms 锁存故障 |
| 电机包络 | 反馈速度 ≤1.0 rad/s，距 arm 位置 ≤0.6 rad |
| 运行时长 | 节点最多 5 秒，执行脚本运动阶段 4 秒 |
| 发布者 | 电机目标话题须仅有本节点；启动及运行时检查冲突 |
| 故障 | 输出一次零后停止刷新；终止态不自动重新 arm，需重启节点 |

电机模式未 arm 且输入/反馈有效时只刷新零目标，便于控制器启用前零保持。
输入无效时不持续续期。故障清零不是机械制动，驱动超时与失能仍是独立保护。

## 软件入口

```bash
# 仅预览，先启动传感器 bridge 和姿态节点：
ros2 run mech_assist_control desk_imu_follow_node
ros2 service call /desk_imu_follow/arm std_srvs/srv/Trigger '{}'
ros2 topic echo /desk_imu_follow/preview_velocity
```

`tools/bench/run_desk_imu_follow.py --preflight` 只查询已启动 manager 的
硬件/速度控制器是否 inactive，不创建控制策略实例、不发布目标、不启用硬件。

显式 `--execute --operator-supervised` 创建唯一 motor 输出实例，经既有 manager
启用硬件、检查静止与数据、启用速度控制器、arm，运动 4 秒，然后由同一发布者
保持零目标 0.7 秒、确认速度 ≤0.1 rad/s，再停用控制器及硬件。
没有输入目标或没有检测到轴运动均记失败，不自动增加增益或前馈。
异常路径尝试停用；无法确认失能时明确要求现场断电，不能记通过。
