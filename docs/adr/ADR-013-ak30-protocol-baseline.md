# ADR-013：协议基线切换到 AK3.0（L07）并重定义 ProtocolProfile

- **Decision ID:** ADR-013
- **Status:** Proposed
- **Date:** 2026-09-01
- **Owner:** 项目负责人
- **Scope:** 当前电机的协议资料基线、`ProtocolProfile` 枚举、profile 实现顺序、`effort` 解锁，以及配置期固定 profile 规则的理由重述

## Status rationale / 状态依据

本 ADR 在任何实现之前提交，符合 `adapter_contract_v1.md` 第 7 条「契约变更先出 ADR」。ADR-012 是先实现后追认的反例，本次不重复。

`Proposed` 表示项目负责人已口头确定基线切换、Kt 可用与力控优先三项，但尚未复核本文写下的**具体范围与边界**。转 `Accepted` 前不得改动 `ProtocolProfile` 枚举。

## Context / 上下文

2026-08-19，项目负责人确认 `ak-series-driver-manual-v1-0-18-for-ak-2-0-robotic-actuator-cn.pdf`（资产 **L02**，AK2.0 V1.0.18）的 CAN 协议与参数适用于当前电机。此后全部协议规划、`ProtocolProfile` 枚举命名、带宽预算和 profile 顺序都建立在这一次确认之上。

2026-09-01，项目负责人更正：真正适用的是 `ak-series-prodcut-manual-v3-2-0-for-ak-3-0-robotic-actuator-cn.pdf`（资产 **L07**，AK3.0 V3.2.0，52 页）。该文件哈希 `41069C18…C5AA` 与 `manifests/assets.yaml` 中 L07 的登记值逐位一致。

**与该口头更正相互独立的客观证据**：

| | L02 覆盖的驱动板 | L07 覆盖的驱动板 |
|---|---|---|
| 型号 | `AK-DRV-V2.1`、`AK-DRV-V2.2`、`AK-DRV-V1.0` | `AK54-4810-1C-A2`、`AK60-4820-1C-A2`、`AK80-4830-1C-A4` |

登记资产 **L14** 是 `CubeMars/驱动板/AKE60-8 驱动板- AK54-4810-1C-A2.rar`——本项目电机的驱动板是 `AK54-4810-1C-A2`，它出现在 L07 §1.2.1，而在 L02 中不存在。这不是同一手册的两个版本，而是**两代不同硬件**。这也解释了此前的一个疑点：L02 的运控/MIT 型号参数表里没有 AKE60-8，因为该电机根本不属于 AK2.0 产品线。

`06_cubemars_material_review.md` 早已完整分析过 L07（力控控制模式 ID、载荷布局、`0x2A`、带宽场景），但因 2026-08-19 的确认而将其定位为「补充交叉依据」。本 ADR 将其提为基线。

## Decision / 决策

1. **协议资料基线由 L02 切换为 L07。** L02 不再是任何协议判断的依据，仅作为历史记录保留在来源册中，并注明不适用及原因。

2. **`ProtocolProfile` 枚举重定义。** `L02ServoExtended` 与 `L02MitStandard` 不再反映事实：AK3.0 的两个命令族**都是 29 位扩展帧**，不存在 11 位标准帧的运控 profile。取而代之的是伺服（控制模式 `{0,1,2,3,4,5,6,15,16}`）与力控（控制模式 ID `8`，三个子模式由载荷内容区分而非由 ID 区分）。这是 FND-005 冻结类型的变更，必须随本 ADR 的 `Accepted` 一并落地。

3. **力控为第一实现 profile，伺服为第二。** 这推翻 2026-08-19 的「伺服优先、运控次之」排序，因为该排序的前提（L02）已不成立。力控是阻抗控制（`Kp·(θ_ref−θ) + Kd·(V_ref−V) + T_ref`），不具有伺服位置模式「以最大转速和加速度到达期望位置」（L07 §3.3.1.4）的冲击风险，更适合机械臂首次接入。

4. **接受 `Kt = 0.7382 N·m/A` 用于本定制机型，`effort [N·m]` 解锁。** L07 §4.2 参数表列出 AKE60-8：KV 80、`Kt = 0.7382`、位置 ±12.56 rad、速度 ±40.0 rad/s、力矩 ±15.0 N·m、Kp 0–500、Kd 0–5（位置与 Kp/Kd 为跨型号合并单元格，已通过阅读第 37 页原图确认，非 `pdftotext` 推测）。手册明确 `T = Kt × Iq` 中 **T 为输出端输出扭矩**。项目负责人于 2026-09-01 明确担保该值适用于本定制双编码器版本。此项命中 ADR-009 自身的重审触发条件第一条，ADR-009 须相应修订。

5. **配置期固定 profile、ACTIVE 期不混发的规则维持不变，但理由必须重写。** 此前的理由隐含「固件做不到」。证据现在指向相反方向：L02 的上位机有「模式切换」页且 §4.4 要求分别上传伺服与 MIT 两套固件，而 **L07 的上位机没有模式切换页**（§3 中唯一的「切换」是中英文切换），§3.3 在同一台连接的电机上依次演示伺服模式与力控模式，§3.4 的固件升级是单一下拉列表。因此一份固件很可能同时接受两个命令族。**规则保留的理由改为：这是本项目的主动选择**——运行期在位置伺服与力控之间混发会造成控制权归属不清，与固件能力无关。任何未来读者不得以「固件其实支持」为由删除该规则。

6. **Golden vector 必须逐条反算验证，不得照抄手册示例。** L07 §4.4.1 力控速度环示例 `00 06 66 7F FF 98 67 FF` 标注「速度设置为 6rad/s」，但 `DATA[5]=0x98` 反解为 **5.3402 rad/s**；应为 `0x9B`，反解得 5.9966 rad/s。同表其余示例全部精确吻合（力矩 2 N·m → 1.99、4 N·m → 4.00、位置 6 rad → 6.029、Kp → 1.95、Kd → 2.00），正是这一点证明位打包与归一化公式无误而示例有误。照抄该行会固化约 11% 的系统性速度误差，且离线测试无法发现。

## Alternatives considered / 替代方案

### A. 维持 L02 为基线，L07 继续作为补充参考

保持现状、改动最小。但驱动板证据表明 L02 描述的是另一代硬件，继续以它为准等于明知错误仍据以实现。拒绝。

### B. 同时支持两套基线，由配置选择

看似稳妥，实则为一个我们并不拥有的硬件世代维护双倍协议面、双倍测试和双倍出错机会，且与「协议 profile 不共用有歧义的打包函数」（`03_mvp_delivery_plan.md`）相冲突。拒绝。

### C. 切换到 L07 单一基线（选定）

与实际硬件一致，消除双倍维护面，并使先前被阻塞的力控 profile 与 `effort` 接口同时解锁。

## Consequences / 后果

### Positive / 正面

- 协议依据与实际驱动板 `AK54-4810-1C-A2` 一致，不再存在跨代引用。
- 先前三项硬阻塞同时解除：AKE60-8 的 Kt、力控归一化常数、输出端转速换算公式（`输出端转速 = ERPM ÷ 极对数 ÷ 减速比`，L07 §4.3.1）。
- 力控优先使首个真实 profile 天然规避伺服位置模式的最大速度冲击风险。
- `06` 中既有的 AK3.0 分析可直接复用，改动以重新定位为主而非重写。

### Negative / 负面与代价

- 12 份文档约 92 处 L02 引用需要处置，`config.hpp` 与其测试需要修改。
- **带宽预算可能不足**：`06` 已算出 AK3.0 场景下 2 电机 + `0x2A` @500 Hz 为 53.6%，超过 50% 平均预算目标；1 kHz 场景 73.6%–97.6% 已被拒绝。力控成为第一 profile 后必须整体重算，结论可能是下调频率目标或不启用 `0x2A`。该重算不得为了迁就既有目标而调整假设。
- 昨日完成的 L02 手册核对成果（`motor1_parameters.md` §9、适配器设计 spec）需按 L07 重做。
- `v0.1.0-foundation-rc2` 及 Foundation 代码不受影响：协议基线错误不触及 core、transport、看门狗，116 项测试依然有效，仅枚举命名需变更。

## Validation / 验证

- `python3 tools/ci/check_adrs.py` 通过，且 ADR-013 在 `docs/adr/README.md` 与规划文档中的反向链接有效。
- `python3 tools/ci/context_check.py` 通过。
- `ProtocolProfile` 变更后跑完整本地验证集：`build_workspace.sh`、`run_sanitizers.sh`、`git diff --check`，并保持既有测试全绿。
- 力控 codec 的每条 golden vector 均以文档化范围反算复核，示例与反算不一致时以反算为准并在测试中注明。
- 本 ADR 未主张任何实机验证；设备启用仍由 ADR-006 与 G0–G3 单独管辖。

## Review triggers / 重审触发

- 供应商确认或否定 `Kt = 0.7382` 对本定制版的适用性，或给出不同的输出端力矩定义；
- 出现证据表明固件**不**同时接受伺服与力控命令族，或表明二者存在互斥前置条件；
- 带宽重算结论要求改变电机 I/O 频率目标或 `0x2A` 启用策略；
- `0x29` 位置字段的编码器来源、方向与零位链路被确认，从而影响机械映射；
- 出现 AK3.0 之后的新世代资料，或实机被证明更换了驱动板。
