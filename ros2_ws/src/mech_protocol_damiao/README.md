# 达妙 DM4340 MIT 协议包

## 当前范围

本包提供标准帧 Classic CAN 的 MIT 报文编解码，以及无I/O的位置/速度/力矩会话。会话本身不会打开 CAN 通道、使能或失能电机、设置零位或发布 ROS 控制接口。可选 ROS 监视节点只接收反馈；已通过独立 `mech_bringup/Dm4340System` 接入生产代码路径，实机验收范围另行记录。

本包与 `ros2_ws/src/mech_protocol_cubemars` 平级，分别拥有自己的库、包清单和测试；两个品牌协议包互不依赖。后续可共用 `mech_control_core` 的总线机制和 `mech_bringup` 的生产组合层，但通用控制器不应加入品牌分支。

## 协议依据

位布局和参考量程来自[达妙官方电机 SDK](https://github.com/dmBots/motor-sdk/blob/main/Python%E4%BE%8B%E7%A8%8B/u2can/DM_CAN.py)中的 `controlMIT`、`__process_packet`、`float_to_uint` 和 `Limit_Param`。SDK 对 DM4340、DM4340_48V 列出的范围为：位置 +/-12.5 rad、速度 +/-10 rad/s、力矩 +/-28 Nm、Kp 0～500、Kd 0～5。

这些只是**报文编码范围**，不是已批准的控制限值或关节限位，也不能证明当前实物电机采用相同的固件参数。调用方必须显式提供量程；代码中的 SDK 数值仅作为命名参考和测试夹具。超范围、NaN 和无穷大输入均直接拒绝，不自动裁剪。

反馈解析保留原始故障码、电机 ID 和末尾两个未经解释的字节。只有总线与反馈 CAN ID 均匹配配置时才接受反馈。上述 SDK 实现没有解释末尾两个字节，因此本包不把它们标成温度。

## 离线会话

官方 SDK 还支持其他控制模式和旧版固件；本包目前只支持与所引用位布局相符的 MIT 数据帧。离线会话必须显式配置固件身份及允许范围、收发 CAN ID、电机 ID、编码量程、有依据的电机轴到关节角映射、关节包络、最大目标偏差、增益和超时时间。

会话只接受新鲜、顺序正确且无故障的反馈；准备目标时和总线发送前都会复核目标。实机已确认的反馈 CAN ID `0x00` 是合法标准帧 ID，不是“未配置”。速度会话使用 MIT `Kp=0`、配置的 `Kd>0`，前馈力矩由 `velocity_feedforward_nm` 设置（默认 0）；正反转随电机轴速度改变符号，零速时前馈为 0。它要求反馈状态为已使能，并显式限制目标速度、反馈速度和反馈力矩。速度目标不能自动使能或失能电机，且主机超时不能代替电机侧失联保护。故障锁存后，必须停用并重新激活；这会清除旧反馈和已准备的帧。调用方在准备或准入失败时还必须撤销总线中该资源的待发送租约。原始电机轴位置或力矩不能直接作为已标定的关节状态发布。

MIT 速度指令的驱动力矩近似为 `Kd * (目标速度 - 实际速度) + 前馈力矩`，因此 `Kp=0`、无前馈时遇到阻力会留下稳态速度误差。2026-10-16 的离体单电机正向台架试验在目标 `0.8 rad/s` 下测得：`Kd=1、前馈=0` 时稳态约 `0.4 rad/s`；`Kd=2、前馈=0` 时为 `0.592 rad/s`；`Kd=2、前馈=0.4 Nm` 时为 `0.782 rad/s`。这是一次空载正向标定，不代表反向、不同负载或人体工况也需要 0.4 Nm。ROS 启动参数 `velocity_feedforward_nm` 默认 `0`，当前 DM4340 配置限制为 `0..0.5 Nm`；只在已经单独验证关节方向、机械边界和电机侧保护的台架配置中显式设置。此次只对台架程序做了实机对照，尚未对含前馈的 ROS 驱动做实机运动验证。

目前不假定命令/反馈 CAN ID、固件版本、CAN 仲裁率、减速比、关节方向、机械零点或安装方式。用户确认电机为 DM4340、使用 MIT 模式，并提到 `115200`；该数值对应的通信通道尚未确认，不能当作 CAN 仲裁率。测试中的 4/6 ms 时间仅是合成夹具，不是 DM4340 默认时序。

## 七路板只接收探针

`dm4340_rx_probe` 是可选台架工具，默认不构建。使用 `-DMECH_BUILD_DAMIAO_RX_PROBE=ON` 构建后，在端口无其他读者、设备权限已授予、板固件版本已确认的前提下运行：

```sh
dm4340_rx_probe /dev/ttyACM1 10 4.8.8
```

设备路径、持续时间和固件版本均为显式输入；这里的路径采用用户新确认的电机通道，版本号只是命令示例，不代表本次已读回固件。探针打开与 CubeMars 相同的串口/USB-CAN 接收链路，发送一次网关 `0x12` 接收转发初始化帧，然后最多监听 30 秒，打印每个原始 CAN 帧的格式、ID、DLC 与载荷。它不调用 CAN 发送接口，不发送电机使能、置零或运动命令。若已独立确认反馈 CAN ID 和电机 ID，可在命令末尾加上这两个参数（十进制或 `0x` 十六进制）尝试 MIT 反馈解码；显示的物理量使用 SDK 参考量程，不是当前实物标定值。

**没有收到帧不等于电机或线路故障**：电机可能不会主动上报，且探针不发起读取或使能。端口打不开时先检查权限和占用，不要改用其他端口猜测。`raw` 和 `decoded` 分别表示网关完整收帧数和匹配已确认 ID 的解码数。

## ROS 2 限时接收监视器

本地达妙 `ROS1 例程` 使用 Noetic、达妙 USB-CAN 设备和启动后运动的控制程序，不能在当前 Humble/七路板上直接运行。可选的 `dm4340_ros_monitor` 默认只复用本工程 USB-CAN 接收链和 MIT 反馈解码；它没有控制订阅者，也不会发送使能、失能或 MIT 运动帧。诊断话题为 `/damiao/monitor/diagnostics`，原始帧包含 CAN ID、格式、DLC 和十六进制载荷。只有明确配置反馈 CAN ID 与电机 ID 时，才附带 SDK 参考量程下的电机轴位置、速度、力矩及原始故障码；这些数值不是经过关节标定的状态。

匹配且状态码正常的 MIT 反馈还会发布 `/damiao/monitor/motor_axis` (`sensor_msgs/JointState`)，名称为 `dm4340_motor_<id>`，单位分别为电机轴 rad、rad/s 和 SDK 参考量程下的 Nm。故障帧不发布状态；反馈停止时该话题也停止更新，订阅者必须自行检查时间戳和诊断。默认不主动查询电机，所以静止电机不主动上报时也可能没有状态消息。`motor_axis` 不是膝关节角，也不是 `ros2_control` 的运动指令入口。

在单独的构建工作区中执行 `colcon build --packages-up-to mech_protocol_damiao --cmake-args -DMECH_BUILD_DAMIAO_ROS_MONITOR=ON` 并加载 `install/setup.bash`，然后在端口无人占用、已确认七路板接口和接收协议版本的条件下限时运行：

```sh
ros2 run mech_protocol_damiao dm4340_ros_monitor --ros-args \
  -p device_path:=/dev/ttyACM1 -p logical_bus:=1 \
  -p board_version_major:=4 -p board_version_minor:=8 \
  -p board_version_patch:=8 -p duration_seconds:=10
```

另开终端运行 `ros2 topic echo /damiao/monitor/diagnostics` 观察诊断。上例 `4.8.8` 是既有解帧兼容性试用值，**不是**当前板固件的实际读回版本；未确认兼容性时不要把无帧或解码失败解释为电机故障。需要解码时额外传入 `-p feedback_can_id:=<已确认十进制ID> -p motor_id:=<已确认十进制ID>`，两项必须同时提供。原始帧和已配置反馈连续 500 ms 未更新时显示过期。监视器最多运行 30 秒，达到期限后主动退出。它不替代生产 ROS2 电机插件，不能控制 DM4340。

对已确认的电机，可额外设置 `-p feedback_can_id:=0 -p motor_id:=2 -p status_query_period_ms:=200` 做限时状态查询。此选项默认 `0`（关闭），允许范围 100..1000 ms；只向标准 CAN ID `0x7FF` 发送带目标电机 ID 的 `0xCC` 状态查询，诊断中的 `status_queries` 记录发送次数。查询需要独占端口，不得与电机控制器或其他上位机同时运行；串口发送成功并不证明电机实际收到查询。

## DM4340 单电机台架闸门

只读检查减速比可用 `dm4340_enable_bench /dev/ttyACM1 --read-gear-ratio`。
它先请求状态，再读取官方 SDK 的 `Gr` 寄存器 20，不发送使能或运动帧。
2026-10-15 本台电机返回原始值 `0x42200000`，按小端浮点解码为 `40.000`；
这不能单独证明 MIT 角度是否已经按减速器输出轴换算。

可选 `dm4340_enable_bench` 用 `-DMECH_BUILD_DAMIAO_ENABLE_BENCH=ON` 构建。它仅面向已核对的单电机台架：控制 CAN ID `0x02`、反馈 CAN ID `0x00`、嵌入式电机 ID `0x02`、七路板接口 `/dev/ttyACM1`（用户 2026-10-14 更正；此前 `/dev/ttyACM3` 的零帧结果不能代表电机通道）。`--status-only` 先向 CAN ID `0x7FF` 发送达妙例程中的定向 `0xCC` 状态刷新请求，最多等待 1.2 秒；**不会使能**。`--enable` 同样先要求收到匹配且无故障的反馈，之后才发送一次 `0xFC` 使能，不发送运动目标，最多等待 500 ms，再尝试发送三次 `0xFD` 失能。串口网关接受发送帧不等于电机收到命令；工具无法证明物理失能，现场必须保留可立即切断电机电源的人和手段。

`--jog` 仅用于无人接触、脱离负载、台架固定且有现场断电手段的首次小幅运动检查。它沿用相同的失能状态预检和短时使能，随后相对当前电机轴位置发送固定 `+0.1 rad`、`Kp=2`、`Kd=0.1`、零前馈的 MIT 目标，最多采集二十次反馈。任一反馈超时、状态异常、位置超出起点 `-0.05..+0.2 rad`、速度绝对值超过 `2 rad/s` 或力矩绝对值超过 `0.5 Nm` 时立即尝试失能。该工具没有独立硬件看门狗；进程或 USB-CAN 链路失效时不能保证失能，因此**不得带人或负载运行**。测试后须独立执行 `--status-only` 确认状态码回到 0。

`--enable-only` 仅在预检状态为 0 时发送一次使能帧，确认反馈状态为 1 后退出；成功路径**不发送失能或运动帧**。它会留下电机处于使能状态，不能依赖工具进程退出自动停机。2026-10-14 用户明确要求保持使能的台架测试中，该模式返回状态 1；之后未发送其他电机指令。

`--slow-5s` 要求电机已使能，发送固定 `0.1 rad/s` 速度目标（`Kp=0`、`Kd=3`、零前馈）五秒，按 10 Hz 读取反馈；相对起点位置限制为 `-0.1..+0.7 rad`、速度绝对值上限 `0.3 rad/s`、力矩绝对值上限 `0.5 Nm`。正常结束发送零速度阻尼指令，确认近零速度后**保持使能**；反馈中断、状态异常或超限时尝试失能。此模式没有独立硬件看门狗，须在有现场断电手段的空载固定台架上运行。

五秒实测结果：预检状态 1、位置 1.055 rad；运行中反馈状态始终 1，力矩约 +0.267..+0.280 Nm，但位置保持 1.055 rad、速度接近 0。零速度指令后力矩回落，独立回查为状态 1、位置 1.055 rad、速度约 0.002 rad/s。**指令已执行，低速旋转未实现。** 在查清机械约束、反馈轴和 MIT 运行条件前，不提高输出继续尝试。

`--read-mode` 只读查询控制模式寄存器 10；2026-10-14 实机读回 `1`，确认 MIT 模式。经台架授权，另加入独立的 `--torque-step`：仅在已使能且 MIT 读回为 1 时，以 `0.1 rad/s`、`Kp=0`、`Kd=5`、零前馈发送约 0.5 秒，理论静止指令约 `0.5 Nm`，逐帧检查状态、位置、速度及 `0.8 Nm` 反馈上限。正常结束发送零速度并保持使能，异常尝试失能；仍无独立硬件看门狗。一次实测反馈峰值 `0.472 Nm`，位移 `0.000 rad`，速度接近零；独立复核状态 `1`、位置 `1.055 rad`。因此增大这一级指令没有解决不转动的问题，不应继续盲目提高力矩。下一步应断电检查输出轴/联轴器是否被锁住，并核对驱动器输出轴编码器及实际机械负载。

后续按要求把 `--torque-step` 的目标速度改为 `1.0 rad/s`，同时将 `Kd` 降为 `0.5`，保持静止时理论指令约 `0.5 Nm`；反馈速度安全阈值仍为 `0.3 rad/s`，因此这只是受限的指令测试，**不能用于验证稳定达到 1 rad/s**。经台架确认后运行一次，反馈峰值 `0.485 Nm`、位移 `0.000 rad`，速度接近零；零速度收尾后独立读回状态 `1`、位置 `1.055 rad`、速度约 `-0.002 rad/s`。上段 `0.472 Nm` 是旧参数的实测结果。两次均无位移，不应继续单纯提高目标速度或力矩。

截图参数复现实验使用独立的 `--gui-2s` 模式：先确认寄存器 10 为 MIT，状态 0 时才发送一次使能并等待状态 1；随后发送 `p_des=0`、`v_des=0.8 rad/s`、`Kp=0`、`Kd=1`、`t_ff=0`，约每 10 ms 一帧，最多 2 秒。截图软件显示约 1 ms 定时发送，此模式**不是严格复现 1 ms 周期**。运行中限制相对位移 `-0.1..1.0 rad`、速度绝对值 `1.0 rad/s`、反馈力矩绝对值 `1.2 Nm`；异常尝试失能，正常结束发送零速度、确认静止并保持使能。2026-10-14 离体固定台架实测：使能前状态 0、位置 `-2.460 rad`，MIT 读回 1；200 帧约 2 秒，反馈峰值 `0.622 Nm`，位移 `+0.779 rad`，稳定运行速度约 `0.4 rad/s`。独立收尾查询：状态 1、位置 `-1.668 rad`、速度约 `-0.002 rad/s`。与之前不转动的试验相比，`Kd` 和发送周期都改变了，不能据此单独判定是哪一项导致转动；这仍是台架工具，不是生产控制器或人体穿戴测试。

`--gui-5s` 保留同一 MIT 指令和约 10 ms 发送周期，将时长扩展到 5 秒、相对位移上限扩展到 `2.5 rad`。经用户确认离体固定及行程后实测 500 帧、5.002 秒：起止位置均为 `-1.668 rad`，速度接近零，反馈力矩约 `0.786 Nm`、峰值 `0.800 Nm`；用户肉眼也未看到转动。零速度收尾后独立读回状态 1、速度约 `-0.002 rad/s`、力矩约 `-0.021 Nm`。在当前停留位置排除正向机械卡滞/限位前，**不得直接重复 5 秒堵转测试或提高力矩**。

`--gui-1ms-2s` 是独立的 2 秒高频台架模式，沿用相同 MIT 参数和位移/速度/力矩边界，在单线程中按 1 ms 单调时钟期限写入网关并轮询反馈；写入延迟超过 3 ms、反馈超过 40 ms 未更新或反馈异常时退出并尝试失能。正常结束发送零速度阻尼指令，确认速度和反馈力矩回落后保持使能。2026-10-14 在离体固定台架上获授权运行一次：2000 次网关写入、1999 组反馈，超过期限 0.5 ms 的写入为 0 次，主机侧最大发送间隔 1.129 ms；反馈峰值 0.800 Nm，但位置仍固定在 -1.668 rad，位移 0.000 rad。独立状态查询显示状态 1、速度 -0.007 rad/s、力矩 -0.021 Nm、温度 30/29 C。该统计是 Jetson 写入 USB 网关的时间，不是 CAN 总线上的逐帧时间戳；结果说明将主机发送周期由约 10 ms 提升到约 1 ms 后，当前位置仍未起转，不能单独归因为主机发送周期过慢。

`--read-timeout` 只读查询达妙例程中参数地址 9 (`TIMEOUT`) 的原始值，不改变电机设置；它与反馈状态码 9（欠压）是不同字段。2026-10-14 设备读回参数地址 9 为 `0`，其单位和对这版固件的实际作用未验证，因此该读数不再作为运动测试的前置门槛。原有 `1.2 Nm` 是反馈超限后的停机阈值，不是发给电机的力矩上限：此前 `v_des=0.8 rad/s, Kd=1` 在静止时约产生 `0.8 Nm` MIT 目标，调高反馈阈值不会让同一指令获得更大驱动力。独立的 `--high-torque-probe` 台架模式现在以 `v_des=1.5 rad/s, Kp=0, Kd=3.2, t_ff=0` 为最终目标（静止时约 `4.8 Nm`），从零速度、`Kd=1` 用前 50 ms 平滑爬升；运动阶段最多 200 ms，位移达到约 `0.2 rad` 即提前进入零速度阻尼收尾。保留 `0.3 rad` 最终位移、`2 rad/s` 速度、`5 Nm` 反馈力矩、`40 ms` 反馈超时和无位移提前退出保护。该模式仍先确认 MIT 模式，异常时尝试失能；但不能把主机侧限幅当作电机失联后的独立停机保障。Kd=3.2 版本尚未实机运行。

2026-10-14 在用户确认离体固定台架、正向行程和现场断电条件后，修改前的固定指令版 `--high-torque-probe` 实机运行一次：运动阶段写入 200 帧、收到 198 帧反馈，主机最大发送间隔 1.213 ms，峰值反馈力矩 1.976 Nm。起始位置 2.000 rad，运动阶段最后记录位移 +0.242 rad；零速度阻尼收尾后独立回读位置 2.284 rad，故最终位移约 +0.284 rad、速度 -0.007 rad/s、力矩 -0.021 Nm、状态 1（仍使能）。程序约 0.311 s 的总时长包含收尾确认，不是 0.311 s 连续运动。上面的实测值不能作为后续平滑爬升版的效果。仅证明本次离体台架短时动作，不证明电机侧失联保护或人体穿戴安全。

`--interactive-mit` 是前台交互台架模式，不设预定时长或位移目标，适用于**离体固定且轴可持续自由旋转**的电机，不适用于存在机械限位的外骨骼机构。它以约 1 ms 周期发送 MIT 目标，前 50 ms 从零速度、`Kd=1` 平滑升至 `1.5 rad/s`、`Kd=3.2`，约每 100 帧打印位置、速度、力矩和状态。操作者在同一个终端按回车后发送零速度阻尼指令，确认速度和力矩回落后保持使能；Ctrl+C、终端断开、反馈超时、反馈超限或发送错误时尝试失能。速度绝对值限制 `2 rad/s`、反馈力矩绝对值限制 `5 Nm`、反馈超时 `40 ms`、主机发送期限超出 `3 ms` 即中止。必须在可直接操作的前台 TTY 运行，普通非交互 SSH 调用会在打开设备前拒绝。电机侧失联停机尚未验证，主机进程崩溃或网关故障时软件无法保证停机，现场必须能立即切断电源；此模式不是生产控制器。

Jetson 本地终端运行：`/tmp/dm4340_gate_ws/install/mech_protocol_damiao/lib/mech_protocol_damiao/dm4340_enable_bench /dev/ttyACM1 --interactive-mit`。远程操作需使用可交互终端（例如 SSH 的 `-tt` 选项），不要将其作为后台进程启动。
